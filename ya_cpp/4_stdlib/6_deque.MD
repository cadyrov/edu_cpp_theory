# 6. Двусторонние очереди

## Суть

`std::deque` - контейнер, в который удобно добавлять и удалять элементы с обоих концов.

```cpp
#include <deque>

std::deque<int> values;
```

Название читается как double-ended queue.

## Пример 1: оба конца

```cpp
#include <deque>
#include <iostream>

int main() {
    std::deque<int> values;

    values.push_back(20);
    values.push_front(10);
    values.push_back(30);

    for (int value : values) {
        std::cout << value << ' ';
    }
}
```

Вывод:

```text
10 20 30
```

## Пример 2: удаление

```cpp
std::deque<int> values{10, 20, 30};

values.pop_front();
values.pop_back();
```

Останется один элемент: `20`.

## Пример 3: доступ по индексу

```cpp
std::deque<int> values{10, 20, 30};

std::cout << values[1] << '\n';
```

У `deque` есть доступ по индексу, но элементы не обязаны лежать одним непрерывным блоком.

## Подводные камни

## 1. Это не vector

```cpp
// &values[0] не значит начало одного большого массива
```

`std::deque` обычно хранит данные блоками.

Если нужен непрерывный буфер, нужен `std::vector`.

## 2. Вставка в середину все еще дорогая

```cpp
values.insert(values.begin() + 2, 42);
```

`deque` хорош для концов, а не для середины.

## 3. Инвалидация сложнее, чем у vector

Операции с `deque` могут инвалидировать итераторы.

Ссылки и указатели ведут себя не так просто, как у `vector`.

## Когда использовать

- часто нужен `push_front`;
- часто нужен `pop_front`;
- нужен доступ по индексу;
- не нужен единый непрерывный буфер.

## Саммари

- `std::deque` удобен для работы с двумя концами.
- `push_front` и `push_back` обычно быстрые.
- Доступ по индексу есть.
- Память не обязана быть непрерывной.
- Для непрерывного массива лучше `std::vector`.
