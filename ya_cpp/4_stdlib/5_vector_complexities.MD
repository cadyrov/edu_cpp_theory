# 5. Сложности вектора

## Суть

`std::vector` быстрый, когда работа идет с концом или по индексам.

Он медленнее, когда нужно часто вставлять или удалять элементы в середине.

## Основные операции

- доступ по индексу - `O(1)`;
- `push_back` - амортизированно `O(1)`;
- вставка в середину - `O(n)`;
- удаление из середины - `O(n)`;
- поиск по значению - `O(n)`.

## Пример 1: быстрый доступ

```cpp
std::vector<int> values{10, 20, 30};

int x = values[1]; // O(1)
```

Вектор может сразу перейти к нужному элементу, потому что элементы лежат подряд.

## Пример 2: добавление в конец

```cpp
std::vector<int> values;

for (int i = 0; i < 1000; ++i) {
    values.push_back(i);
}
```

Обычно это быстро.

Иногда вектор выделяет новый буфер и переносит туда элементы.

## Пример 3: вставка в начало

```cpp
std::vector<int> values{1, 2, 3, 4};

values.insert(values.begin(), 0);
```

Все старые элементы нужно сдвинуть вправо.

## Пример 4: удаление из середины

```cpp
std::vector<int> values{1, 2, 3, 4};

values.erase(values.begin() + 1);
```

Элементы после удаленного места нужно сдвинуть влево.

## Подводные камни

## 1. Амортизированная сложность не значит всегда O(1)

```cpp
values.push_back(x);
```

Обычно быстро, но при нехватке вместимости будет реаллокация.

## 2. Реаллокация инвалидирует ссылки и указатели

```cpp
std::vector<int> values{1, 2, 3};
int* p = &values[0];

values.push_back(4); // может быть реаллокация

// p может стать висячим
```

После роста буфер может переехать.

## 3. reserve помогает при известном размере

```cpp
std::vector<int> values;
values.reserve(1000);
```

Это уменьшает количество реаллокаций.

## 4. shrink_to_fit не обязан освобождать память

```cpp
values.shrink_to_fit();
```

Это просьба к контейнеру, а не гарантия.

## Саммари

- Индексация вектора - `O(1)`.
- Добавление в конец - амортизированно `O(1)`.
- Вставка и удаление в середине - `O(n)`.
- Реаллокация может инвалидировать ссылки, указатели и итераторы.
- `reserve` полезен, когда заранее известен ожидаемый размер.
