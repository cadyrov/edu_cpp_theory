# 5. Сложности вектора

## Суть

`std::vector` быстрый, когда работа идет с концом, индексами и стандартными алгоритмами для непрерывной памяти.

Он медленнее, когда нужно часто вставлять или удалять элементы в начале или середине.

## Основные операции

- доступ по индексу - `O(1)`;
- `at()` - `O(1)`;
- `begin()`, `end()`, `size()` - `O(1)`;
- разность итераторов - `O(1)`;
- `push_back` - амортизированно `O(1)`;
- `pop_back` - `O(1)`;
- вставка в середину - `O(N)`;
- удаление из середины - `O(N)`;
- линейный поиск через `std::find` - `O(N)`;
- сортировка через `std::sort` - `O(NlogN)`;
- бинарный поиск по отсортированному вектору - `O(logN)`.

## Почему доступ O(1)

Элементы `std::vector` лежат непрерывно.

Вектор знает указатель на первый элемент и размер элемента.

```cpp
std::vector<int> values{10, 20, 30};

int x = values[1];  // O(1)
int y = values.at(1); // O(1)
```

Итераторы `std::vector` поддерживают произвольный доступ.

```cpp
auto distance = values.end() - values.begin(); // O(1)
```

Они также являются contiguous iterators: элементы идут подряд в памяти.

## Добавление в конец

```cpp
std::vector<int> values;

values.push_back(1);
values.push_back(2);
values.push_back(3);
```

Обычно `push_back` стоит `O(1)`.

Но если `size() == capacity()`, вектор делает реаллокацию:

1. выделяет новый буфер;
2. переносит старые элементы;
3. добавляет новый элемент;
4. освобождает старый буфер.

Поэтому `push_back` амортизированно `O(1)`, но отдельный вызов может стоить `O(N)`.

`pop_back` стоит `O(1)`, потому что реаллокации при удалении с конца обычно нет.

## Вставка и удаление в середине

```cpp
std::vector<int> values{1, 2, 3, 4};

values.insert(values.begin() + 1, 10);
```

Элементы справа от позиции вставки нужно сдвинуть.

В худшем случае это `O(N)`.

```cpp
values.erase(values.begin() + 2);
```

При удалении элементы справа тоже сдвигаются, поэтому это `O(N)`.

## Поиск и сортировка

В обычном `std::vector` элементы не упорядочены.

```cpp
std::find(values.begin(), values.end(), 42); // O(N)
```

Если вектор отсортирован, можно использовать бинарный поиск.

```cpp
std::sort(values.begin(), values.end()); // O(NlogN)

auto it = std::lower_bound(values.begin(), values.end(), 42); // O(logN)
```

Важно: `lower_bound` корректен только на отсортированном диапазоне.

## vector<bool>

`std::vector<bool>` - особенная специализация.

Она может хранить значения битово, а не как отдельные `bool`.

```cpp
std::vector<bool> flags{true, false, true};
```

Из-за этого `flags[0]` возвращает не `bool&`, а proxy-объект.

```cpp
// bool* p = &flags[0]; // ошибка
```

Последствия:

- привычный generic-код может не скомпилироваться;
- разные элементы могут физически лежать в одном машинном слове;
- одновременная модификация разных элементов в разных потоках может быть небезопасной;
- для создания элементов не используется обычный `allocator_traits::construct`.

У `vector<bool>` есть специальный метод:

```cpp
flags.flip();
```

Если нужна обычная семантика элементов, часто проще использовать `std::vector<char>`.

Если нужен фиксированный набор битов, можно использовать `std::bitset`.

## constexpr vector

Начиная с C++20, `std::vector` можно использовать внутри `constexpr`-вычислений.

```cpp
constexpr int sum() {
    std::vector<int> values{1, 2, 3};

    int result = 0;
    for (int value : values) {
        result += value;
    }

    return result;
}

static_assert(sum() == 6);
```

Это позволяет писать нетривиальные compile-time алгоритмы.

Но динамическая память, выделенная в constexpr-контексте, должна быть освобождена в том же constexpr-контексте.

Поэтому нельзя просто получить `constexpr std::vector` как долгоживущий результат.

```cpp
constexpr std::vector<int> make_vector() {
    return {1, 2, 3};
}

// constexpr auto values = make_vector(); // обычно ошибка
```

Зато `vector` можно использовать внутри constexpr-функции и вернуть обычный результат.

```cpp
constexpr int second_smallest() {
    std::vector<int> values{3, 1, 2};
    std::nth_element(values.begin(), values.begin() + 1, values.end());
    return values[1];
}

static_assert(second_smallest() == 2);
```

## Подводные камни

## 1. Амортизированная сложность не значит всегда O(1)

```cpp
values.push_back(x);
```

Обычно быстро, но при нехватке вместимости будет реаллокация.

## 2. Реаллокация инвалидирует ссылки и указатели

```cpp
std::vector<int> values{1, 2, 3};
int* p = values.data();

values.push_back(4); // может быть реаллокация

// p может стать висячим
```

После роста буфер может переехать.

## 3. reserve помогает при известном размере

```cpp
std::vector<int> values;
values.reserve(1000);
```

Это уменьшает количество реаллокаций.

## 4. shrink_to_fit не обязан освобождать память

```cpp
values.shrink_to_fit();
```

Это просьба к контейнеру, а не гарантия.

## 5. lower_bound требует сортировку

```cpp
std::lower_bound(values.begin(), values.end(), x);
```

Если диапазон не отсортирован, результат использовать нельзя.

## 6. vector<bool> не обычный vector

```cpp
std::vector<bool> flags{true, false};
```

Не рассчитывай получить `bool&` или `bool*` на элемент.

## Саммари

- Индексация вектора - `O(1)`.
- `at()` тоже `O(1)`, но проверяет границы.
- Разность итераторов `vector` - `O(1)`.
- Добавление в конец - амортизированно `O(1)`.
- Отдельный `push_back` может стоить `O(N)` из-за реаллокации.
- Удаление с конца - `O(1)`.
- Вставка и удаление в середине - `O(N)`.
- Линейный поиск - `O(N)`.
- Сортировка - `O(NlogN)`.
- Бинарный поиск по отсортированному вектору - `O(logN)`.
- Реаллокация может инвалидировать ссылки, указатели и итераторы.
- `std::vector<bool>` возвращает proxy-объект вместо обычной ссылки на `bool`.
- `std::vector` можно использовать внутри `constexpr`-вычислений с C++20.
