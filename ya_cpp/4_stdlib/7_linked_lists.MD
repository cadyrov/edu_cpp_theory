# 7. Связные списки

## Суть

Связный список хранит элементы в отдельных узлах.

Логически элементы идут друг за другом, но в памяти каждый узел может лежать в своей области.

В стандартной библиотеке есть:

- `std::forward_list` - односвязный список;
- `std::list` - двусвязный список.

## Устройство

Узел `forward_list` хранит значение и указатель на следующий узел.

```cpp
template <class T>
struct Node {
    Node* next;
    T value;
};
```

Узел `list` хранит значение, указатель на следующий узел и указатель на предыдущий.

```cpp
template <class T>
struct Node {
    Node* next;
    Node* prev;
    T value;
};
```

Из-за этого `std::list` тратит больше памяти на элемент, но умеет удобно идти в обе стороны.

`std::forward_list` экономнее по памяти, но умеет идти только вперед.

## Пример 1: std::list

```cpp
#include <iostream>
#include <list>

int main() {
    std::list<int> values{10, 20, 30};

    values.push_front(5);
    values.push_back(40);

    for (int value : values) {
        std::cout << value << ' ';
    }
}
```

Вывод:

```text
5 10 20 30 40
```

## Пример 2: вставка по итератору

```cpp
std::list<int> values{10, 30};

auto it = values.begin();
++it;

values.insert(it, 20);
```

Вставка перед уже найденной позицией не сдвигает остальные элементы.

## Пример 3: удаление

```cpp
std::list<int> values{10, 20, 30};

auto it = values.begin();
++it;

values.erase(it);
```

Удаляется элемент `20`.

Если итератор уже есть, удаление стоит `O(1)`.

## Пример 4: std::forward_list

```cpp
#include <forward_list>

std::forward_list<int> values{10, 30};

auto before = values.before_begin();
++before;

values.insert_after(before, 20);
```

У `forward_list` операции вставки и удаления работают через позицию перед нужным местом.

Поэтому есть методы `insert_after` и `erase_after`.

## Пример 5: splice

`std::list::splice` переносит узлы между списками без копирования элементов.

```cpp
std::list<int> a{1, 2};
std::list<int> b{3, 4, 5};

a.splice(a.end(), b);
```

После этого:

- `a` содержит `1 2 3 4 5`;
- `b` пустой.

Можно переносить и часть списка:

```cpp
std::list<int> a{1, 2, 3, 4, 5};
std::list<int> b;

b.splice(b.begin(), a, std::next(a.begin(), 2), a.end());
```

Теперь `b` содержит `3 4 5`, а `a` содержит `1 2`.

## Пример 6: LRU cache

Список полезен, когда элемент нужно быстро перенести в начало, если уже есть итератор на него.

Типичный пример - LRU cache:

- `std::list` хранит элементы в порядке использования;
- `std::unordered_map` хранит ключ и итератор в список;
- при обращении элемент переносится в начало через `splice`.

Именно map дает быстрый поиск по ключу.

Сам список не ищет по ключу за `O(1)`.

## Стоимость операций

- доступ к произвольному элементу - `O(N)`;
- поиск через `std::find` - `O(N)`;
- вставка по уже известному итератору - `O(1)`;
- удаление по уже известному итератору - `O(1)`;
- `push_front` - `O(1)`;
- `pop_front` - `O(1)`;
- `push_back` у `std::list` - `O(1)`;
- `pop_back` у `std::list` - `O(1)`;
- `splice` у `std::list` - переносит узлы без копирования элементов.

Важно: вставка в "любое место" стоит `O(1)` только если позиция уже найдена.

Если позицию сначала надо искать, общий cost будет `O(N)`.

## Подводные камни

## 1. Нет доступа по индексу

```cpp
// values[0] // ошибка
```

Чтобы найти элемент, нужно пройти список от начала.

## 2. forward_list не имеет size()

```cpp
std::forward_list<int> values{1, 2, 3};

auto n = std::distance(values.begin(), values.end());
```

У `forward_list` нет `size()`, чтобы не хранить лишнее состояние.

Подсчет размера стоит `O(N)`.

## 3. Плохая локальность памяти

Элементы разбросаны по памяти.

Проход по списку часто медленнее, чем по `std::vector`.

## 4. Вставка быстрая только если позиция уже найдена

```cpp
auto it = std::find(values.begin(), values.end(), 20);
values.insert(it, 10);
```

Поиск позиции стоит `O(N)`.

## 5. Лишняя память на связи

Каждый узел хранит не только значение, но и указатели.

`std::forward_list` хранит один указатель на узел.

`std::list` обычно хранит два.

## 6. Не путать с доступом по ключу

Список сам по себе не дает быстрого поиска по ключу.

Для этого рядом используют `std::unordered_map` или `std::map`.

## Когда использовать

Связные списки нужны редко.

Обычно `std::vector` быстрее и проще.

`std::forward_list` имеет смысл, если нужно экономить память и достаточно движения вперед.

`std::list` имеет смысл, если:

- часто есть готовый итератор на место вставки или удаления;
- важна стабильность итераторов;
- нужно переносить элементы между списками через `splice`.

## Саммари

- `std::forward_list` и `std::list` хранят элементы в отдельных узлах.
- Логический порядок элементов сохраняется, но память не непрерывная.
- `std::forward_list` - односвязный список.
- `std::list` - двусвязный список.
- `std::forward_list` экономит память, потому что хранит меньше указателей.
- У `std::forward_list` нет `size()`.
- Доступ к произвольному элементу стоит `O(N)`.
- Вставка и удаление по уже известной позиции стоят `O(1)`.
- Если позицию нужно сначала найти, общий cost будет `O(N)`.
- Список сам не дает быстрого поиска по ключу.
- Для поиска по ключу список часто комбинируют с `std::unordered_map`.
- `std::list::splice` переносит узлы без копирования элементов.
