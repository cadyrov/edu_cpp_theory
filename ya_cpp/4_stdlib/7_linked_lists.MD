# 7. Связные списки

## Суть

Связный список хранит элементы не подряд.

Каждый узел хранит значение и ссылки на соседние узлы.

В стандартной библиотеке есть:

- `std::list` - двусвязный список;
- `std::forward_list` - односвязный список.

## Пример 1: std::list

```cpp
#include <iostream>
#include <list>

int main() {
    std::list<int> values{10, 20, 30};

    values.push_front(5);
    values.push_back(40);

    for (int value : values) {
        std::cout << value << ' ';
    }
}
```

Вывод:

```text
5 10 20 30 40
```

## Пример 2: вставка по итератору

```cpp
std::list<int> values{10, 30};

auto it = values.begin();
++it;

values.insert(it, 20);
```

Вставка перед найденной позицией не сдвигает остальные элементы.

## Пример 3: удаление

```cpp
std::list<int> values{10, 20, 30};

auto it = values.begin();
++it;

values.erase(it);
```

Удаляется элемент `20`.

## Подводные камни

## 1. Нет доступа по индексу

```cpp
// values[0] // ошибка
```

Чтобы найти элемент, нужно пройти список.

## 2. Плохая локальность памяти

Элементы разбросаны по памяти.

Проход по списку часто медленнее, чем по `std::vector`.

## 3. Вставка быстрая только если позиция уже найдена

```cpp
auto it = std::find(values.begin(), values.end(), 20);
values.insert(it, 10);
```

Поиск позиции стоит `O(n)`.

## 4. Лишняя память на связи

Каждый узел хранит не только значение, но и указатели.

## Когда использовать

Связные списки нужны редко.

Обычно `std::vector` быстрее и проще.

`std::list` имеет смысл, если важна стабильность итераторов и часто есть готовая позиция для вставки/удаления.

## Саммари

- `std::list` хранит элементы в отдельных узлах.
- Доступа по индексу нет.
- Вставка и удаление быстрые только при уже известной позиции.
- Проход часто хуже, чем у `std::vector`.
- В обычном коде сначала стоит рассмотреть `std::vector`.
