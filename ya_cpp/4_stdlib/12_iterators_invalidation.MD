# 12. Итераторы и инвалидация

## Суть

Инвалидация означает, что итератор, ссылка или указатель больше нельзя использовать.

Контейнер изменился, и старый доступ перестал указывать на тот же элемент.

```cpp
std::vector<int> values{1, 2, 3};

auto it = values.begin();
int& ref = values[0];

values.resize(1024); // может быть реаллокация

// it и ref могут быть невалидны
```

Правила зависят от контейнера и операции.

## std::vector

`std::vector` хранит элементы в одном непрерывном буфере.

Если при вставке происходит реаллокация, инвалидируются все итераторы, ссылки и указатели на элементы.

```cpp
std::vector<int> values{1, 2, 3};

auto it = values.begin();

values.push_back(4); // может быть реаллокация

// *it использовать нельзя
```

Если реаллокации нет, при вставке инвалидируется позиция вставки и все элементы правее.

```cpp
std::vector<int> values{1, 2, 4, 5};
values.reserve(100);

auto before = values.begin() + 1; // 2
auto after = values.begin() + 3;  // 5

values.insert(values.begin() + 2, 3);

// before валиден
// after невалиден
```

`erase` инвалидирует удаленный элемент и все элементы правее.

```cpp
std::vector<int> values{1, 2, 3, 4};

auto it = values.begin() + 1;
values.erase(it);

// it невалиден
```

## vector и цикл

Опасно менять `vector` внутри range-based for.

```cpp
for (const auto& value : values) {
    values.push_back(value); // может инвалидировать итераторы цикла
}
```

Range-based for внутри использует итераторы `begin()` и `end()`.

При реаллокации они становятся невалидными.

Если нужно добавлять элементы во время обхода, часто безопаснее использовать индекс.

```cpp
for (std::size_t i = 0; i < values.size(); ++i) {
    if (need_more(values[i])) {
        values.push_back(make_value());
    }
}
```

Но не храни ссылку на элемент через модификацию вектора.

```cpp
const auto& value = values[i];
values.push_back(42);

// value может стать невалидной ссылкой
```

## erase возвращает новый итератор

```cpp
std::vector<int> values{1, 2, 3, 4};

for (auto it = values.begin(); it != values.end();) {
    if (*it % 2 == 0) {
        it = values.erase(it);
    } else {
        ++it;
    }
}
```

После `erase` нужно использовать возвращенный итератор.

## std::deque

У `std::deque` данные лежат блоками.

Вставка в начало или конец инвалидирует все итераторы, но ссылки на остальные элементы остаются валидными.

```cpp
std::deque<int> values{1, 2, 3};

auto it = values.begin();
int& ref = values[0];

values.push_front(0);

// it невалиден
// ref валидна
```

Вставка или удаление в середине инвалидирует итераторы и ссылки.

```cpp
std::deque<int> values{1, 2, 3, 4};

int& ref = values[0];
values.insert(values.begin() + 2, 10);

// ref может быть невалидна
```

`pop_front` инвалидирует итератор и ссылку на удаленный первый элемент.

`pop_back` инвалидирует итератор и ссылку на удаленный последний элемент, а также старый `end()`.

## std::list и std::forward_list

Списки хранят элементы в отдельных узлах.

Вставка не инвалидирует итераторы и ссылки на существующие элементы.

```cpp
std::list<int> values{1, 3};

auto it = values.begin();
values.insert(std::next(values.begin()), 2);

std::cout << *it << '\n'; // ok
```

Удаление инвалидирует только итераторы и ссылки на удаленные элементы.

```cpp
std::list<int> values{1, 2, 3};

auto first = values.begin();
auto second = std::next(first);

values.erase(second);

std::cout << *first << '\n'; // ok
```

Правильное удаление в цикле:

```cpp
for (auto it = values.begin(); it != values.end();) {
    if (*it % 2 == 0) {
        it = values.erase(it);
    } else {
        ++it;
    }
}
```

## std::array

`std::array` не меняет размер.

Операций вставки и удаления нет, поэтому обычной инвалидации из-за роста контейнера нет.

Но `swap` меняет значения в тех же ячейках памяти.

```cpp
std::array<int, 3> a{1, 3, 5};
std::array<int, 3> b{2, 4, 6};

auto it = a.begin();

std::swap(a, b);

// it указывает в a, но теперь там значение 2
```

Итератор не повис, но логически может начать указывать не на то значение, которое ожидалось.

## std::map

`std::map` хранит элементы в узлах дерева.

Вставка через `insert` и `emplace` не инвалидирует итераторы и ссылки.

```cpp
std::map<int, char> values{{1, 'a'}, {2, 'b'}};

auto it = values.find(1);
const auto& ref = *it;

values.emplace(3, 'c');

// it и ref валидны
```

`erase` инвалидирует только удаленный элемент.

```cpp
values.erase(it);

// it и ref на удаленный элемент невалидны
```

`extract` инвалидирует итератор на извлеченный элемент, но ссылки на сам элемент остаются валидными, пока жив node handle.

## std::unordered_map

У `std::unordered_map` правила похожи на `std::map`, но есть `rehash`.

Если вставка вызвала `rehash`, инвалидируются все итераторы.

Ссылки на элементы при `rehash` остаются валидными.

```cpp
std::unordered_map<int, char> values{{1, 'a'}, {2, 'b'}};

auto it = values.find(1);
const auto& ref = *it;

values.rehash(1024);

// it невалиден
// ref валидна
```

`erase` инвалидирует только удаленный элемент.

## swap контейнеров

`std::swap` контейнеров обычно не инвалидирует итераторы и ссылки.

Они продолжают указывать на те же элементы, но эти элементы теперь принадлежат другому контейнеру.

```cpp
std::vector<int> a{1, 2};
std::vector<int> b{3, 4};

auto it = a.begin();

std::swap(a, b);

// *it == 1, но элемент теперь внутри b
```

Для `std::array` ситуация другая: элементы не переезжают между буферами, а меняются значениями.

## Как искать такие ошибки

Инвалидацию сложно ловить глазами.

Помогают:

- сборка с `-DGLIBCXX_DEBUG`;
- статические анализаторы;
- AddressSanitizer.

## Подводные камни

## 1. Нельзя увеличивать стертый итератор

```cpp
for (auto it = values.begin(); it != values.end(); ++it) {
    if (*it == 0) {
        values.erase(it); // после этого ++it опасен
    }
}
```

Нужно писать цикл без `++it` в заголовке и брать результат `erase`.

## 2. reserve может инвалидировать

```cpp
auto it = values.begin();

values.reserve(1000);

// it может стать невалидным
```

Если память была перевыделена, старые итераторы больше не годятся.

## 3. end() тоже может инвалидироваться

```cpp
auto last = values.end();
values.push_back(42);
```

Старый `end()` после изменения контейнера лучше не использовать.

## 4. Индекс не спасает ссылку

```cpp
const auto& item = values[i];
values.push_back(new_item);

// item может стать невалидным
```

После изменения `vector` заново обращайся через `values[i]`.

## 5. unordered_map может сделать rehash

```cpp
auto it = map.find(key);
map.emplace(other_key, value);

// it может стать невалидным, если был rehash
```

Если нужно избежать этого, заранее используй `reserve`.

## Саммари

- Инвалидация делает старые итераторы, ссылки или указатели непригодными.
- У `vector` реаллокация инвалидирует все итераторы, ссылки и указатели.
- Если реаллокации нет, вставка в `vector` инвалидирует позицию вставки и все правее.
- `vector::erase` инвалидирует удаленный элемент и все правее.
- После `erase` используй возвращенный итератор.
- У `deque` вставка на концах инвалидирует итераторы, но не ссылки на остальные элементы.
- У `deque` вставка и удаление в середине инвалидируют итераторы и ссылки.
- У `list` и `forward_list` вставка не инвалидирует существующие итераторы и ссылки.
- У списков удаление инвалидирует только удаленные элементы.
- У `array` нет роста, но `swap` меняет значения в тех же ячейках.
- У `map` вставка не инвалидирует итераторы и ссылки, удаление инвалидирует удаленный элемент.
- У `unordered_map` `rehash` инвалидирует все итераторы, но не ссылки.
- `swap` контейнеров обычно сохраняет итераторы на элементы, но элементы оказываются в другом контейнере.
