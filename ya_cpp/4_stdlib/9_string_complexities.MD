# 9. Сложности строк

## Суть

`std::string` похож на `std::vector<char>`.

Он хранит символы непрерывно, имеет размер, вместимость и может делать реаллокации.

Но у строк есть отдельные оптимизации хранения: COW и SSO.

## Основные операции

- доступ по индексу - `O(1)`;
- `at()` - `O(1)`;
- `size()` - `O(1)`;
- добавление в конец - амортизированно `O(1)`;
- вставка в середину - `O(N)`;
- удаление из середины - `O(N)`;
- `substr` - `O(N)` по размеру подстроки;
- линейный поиск символа - `O(N)`;
- поиск подстроки - зависит от реализации, но обычно не дешевле линейного прохода.

## Shallow copy и deep copy

Поверхностное копирование копирует только указатель, размер и вместимость.

Это быстро, но два объекта начинают смотреть на один буфер.

```cpp
// плохая идея для владеющей строки
data_ = other.data_;
size_ = other.size_;
capacity_ = other.capacity_;
```

Глубокое копирование создает новый буфер и копирует символы.

Это безопаснее, но стоит `O(N)`.

`std::string` ведет себя как владеющий объект: копия строки независима от оригинала.

## COW

COW = copy on write.

Идея: при копировании строки буфер временно общий, а реальная копия делается только при попытке изменить строку.

Для этого нужен счетчик ссылок.

До C++11 такой подход встречался чаще.

Для современного `std::string` COW плохо подходит из-за требований к итераторам, ссылкам и инвалидации.

Но похожий подход можно встретить в других библиотеках.

## SSO

SSO = short string optimization.

Короткая строка может храниться прямо внутри объекта `std::string`, без динамической аллокации.

```cpp
std::string short_text = "hello";
std::string long_text(1000, 'x');
```

Короткая строка часто не ходит в кучу.

Длинная строка обычно хранит символы в динамической памяти.

Размер SSO-буфера зависит от реализации.

На него нельзя завязывать логику программы.

## Пример 1: reserve

```cpp
std::string s;
s.reserve(1000);

for (int i = 0; i < 1000; ++i) {
    s += 'x';
}
```

`reserve` уменьшает количество реаллокаций при сборке большой строки.

## Пример 2: дорогая конкатенация

```cpp
std::string result;

for (const std::string& part : parts) {
    result += part;
}
```

Без `reserve` строка может много раз перевыделять память.

## Пример 3: substr копирует

```cpp
std::string s = "Hello World";

std::string part = s.substr(6);
```

`substr` создает новую строку.

Если нужна невладеющая подстрока, используют `std::string_view`.

## constexpr string

Начиная с C++20, многие операции `std::string` можно использовать в `constexpr`.

```cpp
constexpr std::size_t count_spaces(std::string s) {
    return std::count(s.begin(), s.end(), ' ');
}

static_assert(count_spaces("Hello World") == 1);
```

Это позволяет писать compile-time helper-функции для строк.

Но есть ограничение: динамическая память, выделенная в constexpr-контексте, не может просто стать runtime-памятью.

Поэтому длинную строку, которая требует динамической аллокации, обычно нельзя вернуть как результат `constexpr`-вычисления.

```cpp
constexpr std::string make_long() {
    return std::string(1024, 'x');
}

// constexpr auto s = make_long(); // обычно ошибка
```

Маленькая строка может пройти из-за SSO, но это зависит от реализации.

## Подводные камни

## 1. Вставка в начало дорогая

```cpp
s.insert(s.begin(), 'x');
```

Все символы придется сдвигать.

## 2. substr копирует

```cpp
auto part = s.substr(10, 5);
```

Это новая строка и новая память.

## 3. SSO не гарантирует конкретный размер

Короткая строка может храниться внутри самого объекта `std::string`.

Но размер короткого буфера зависит от реализации стандартной библиотеки.

## 4. Указатели инвалидируются

```cpp
const char* p = s.data();

s += "text";

// p может стать невалидным
```

При реаллокации буфер переезжает.

## 5. constexpr string имеет ограничения

`std::string` можно использовать внутри `constexpr`-алгоритма.

Но не любую строку можно вернуть как `constexpr`-результат, если ей нужна динамическая память.

## Саммари

- `std::string` имеет размер и вместимость.
- Символы строки лежат непрерывно.
- Индексация - `O(1)`.
- Добавление в конец - амортизированно `O(1)`.
- Вставка и удаление в середине - `O(N)`.
- `reserve` полезен при сборке большой строки.
- `substr` копирует.
- Изменение строки может инвалидировать указатели на ее данные.
- Shallow copy копирует только указатели, deep copy копирует буфер.
- COW копирует буфер только при изменении, но для современного `std::string` обычно не используется.
- SSO хранит короткие строки внутри объекта без динамической аллокации.
- `std::string` можно использовать в `constexpr`-вычислениях с C++20.
- Длинную строку с динамической памятью нельзя просто вернуть как `constexpr`-результат.
