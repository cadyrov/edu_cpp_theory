# 15. Плоские контейнеры

## Суть

Плоский контейнер хранит данные в последовательном буфере, но использует их как ассоциативный контейнер.

В C++23 появились:

- `std::flat_set`;
- `std::flat_map`.

Идея: отсортированный `std::vector` часто быстрее дерева при поиске и обходе из-за локальности памяти.

## Отличие от set/map

`std::set` и `std::map` обычно хранят элементы в узлах дерева.

`std::flat_set` и `std::flat_map` хранят данные в контейнерах вроде `std::vector`.

```cpp
template <
    class Key,
    class Compare = std::less<Key>,
    class KeyContainer = std::vector<Key>
>
class flat_set;
```

`std::flat_map` обычно хранит ключи и значения отдельно:

```cpp
template <
    class Key,
    class T,
    class Compare = std::less<Key>,
    class KeyContainer = std::vector<Key>,
    class MappedContainer = std::vector<T>
>
class flat_map;
```

Отдельное хранение ключей повышает плотность ключей в памяти и может ускорять поиск.

## Пример: set на vector

До C++23 похожую идею можно сделать вручную.

```cpp
#include <algorithm>
#include <vector>

std::vector<int> values{10, 30, 20, 10};

std::sort(values.begin(), values.end());
values.erase(std::unique(values.begin(), values.end()), values.end());
```

Получается отсортированный набор уникальных значений.

## Поиск

```cpp
bool contains(const std::vector<int>& values, int x) {
    return std::binary_search(values.begin(), values.end(), x);
}
```

Поиск по отсортированному вектору стоит `O(log N)`.

У `std::flat_set` и `std::flat_map` поиск тоже логарифмический.

На практике он может быть быстрее, чем у `std::set` и `std::map`, потому что данные лежат плотнее.

## Вставка

```cpp
void insert_unique(std::vector<int>& values, int x) {
    auto it = std::lower_bound(values.begin(), values.end(), x);

    if (it == values.end() || *it != x) {
        values.insert(it, x);
    }
}
```

Позиция ищется за `O(log N)`.

Но сама вставка может сдвинуть элементы вправо.

Поэтому вставка в плоский контейнер в худшем случае стоит `O(N)`.

## Преимущества

- меньше памяти на элемент;
- нет узлов дерева и лишних указателей;
- быстрый обход;
- хороший cache locality;
- поиск часто быстрее на практике;
- итераторы произвольного доступа.

Для `std::set` узел обычно хранит не только значение, но и несколько указателей и служебные поля.

У плоского контейнера элемент хранится плотнее.

## Недостатки

- вставка и удаление могут быть дорогими;
- реаллокация инвалидирует итераторы и ссылки;
- элементы должны быть перемещаемыми;
- гарантия исключений слабее, если перемещение элементов может бросить;
- C++23 и поддержка библиотеки могут быть недоступны.

## Когда использовать

`std::flat_map` и `std::flat_set` стоит рассматривать, если:

- элементов немного;
- вставки редкие;
- поисков много;
- важна память;
- важен быстрый проход по всем элементам.

Обычные `std::map` и `std::set` лучше, если:

- вставки и удаления частые;
- нельзя инвалидировать итераторы;
- тип нельзя эффективно перемещать;
- нужна стабильность узлов.

## Bulk load

Если нужно добавить много элементов сразу, часто выгоднее:

1. собрать данные в `std::vector`;
2. отсортировать;
3. удалить дубликаты;
4. передать контейнер в `flat_set`.

```cpp
std::vector<int> keys = load_keys();

std::sort(keys.begin(), keys.end());
keys.erase(std::unique(keys.begin(), keys.end()), keys.end());

std::flat_set<int> fs;
fs.replace(std::move(keys));
```

Так можно избежать множества отдельных вставок со сдвигами.

## extract и replace

Плоские контейнеры дают доступ к внутренним контейнерам.

```cpp
std::flat_set<int> fs = {5, 3, 1, 4, 2};

auto keys = fs.extract();

keys.push_back(6);
keys.push_back(0);

std::sort(keys.begin(), keys.end());
keys.erase(std::unique(keys.begin(), keys.end()), keys.end());

fs.replace(std::move(keys));
```

`extract` извлекает внутренний контейнер.

`replace` вставляет его обратно.

Перед `replace` данные должны быть отсортированы и соответствовать инвариантам контейнера.

## sorted_unique

Если данные уже отсортированы и уникальны, можно сообщить это контейнеру.

```cpp
std::vector<int> keys{1, 2, 3, 4};

std::flat_set<int> fs(std::sorted_unique, std::move(keys));
```

Также можно вставлять отсортированный диапазон.

```cpp
std::vector<int> more{5, 6, 7};

fs.insert(std::sorted_unique, more.begin(), more.end());
```

Важно: если передать неотсортированные или неуникальные данные как `sorted_unique`, поведение может быть неопределенным.

## Подводные камни

## 1. Нужно сохранять сортировку

```cpp
values.push_back(5); // может сломать инвариант
```

После обычного `push_back` бинарный поиск может стать некорректным.

## 2. Вставка дорогая

Вставка в середину последовательного буфера стоит `O(N)`.

Плоские контейнеры хороши, когда чтения больше, чем изменений.

## 3. Инвалидация как у vector

При реаллокации старые указатели, ссылки и итераторы становятся невалидными.

Даже без реаллокации вставка и удаление могут сдвинуть элементы.

## 4. sorted_unique требует честных данных

```cpp
std::flat_set<int> fs(std::sorted_unique, std::move(keys));
```

Если `keys` не отсортирован или содержит дубликаты, это ошибка использования.

## 5. Не всегда быстрее

Плоский контейнер может проиграть дереву при частых вставках и удалениях.

Выбор нужно делать по сценарию: частые поиски и редкие изменения - хороший кандидат.

## Саммари

- `std::flat_set` и `std::flat_map` появились в C++23.
- Они хранят данные в последовательных контейнерах, обычно `std::vector`.
- `std::flat_set` хранит отсортированный набор ключей.
- `std::flat_map` хранит ключи и значения в отдельных контейнерах.
- Поиск стоит `O(log N)` и часто быстрее на практике из-за локальности памяти.
- Обход быстрый, потому что элементы лежат подряд.
- Вставка и удаление стоят `O(N)` из-за сдвига элементов.
- Итераторы произвольного доступа.
- Итераторы и ссылки нестабильны при вставке и удалении.
- Типы элементов должны быть перемещаемыми.
- `extract` и `replace` позволяют массово менять внутренний контейнер.
- `std::sorted_unique` можно использовать только для уже отсортированных уникальных данных.
- Плоские контейнеры подходят для редких изменений и частого поиска.
