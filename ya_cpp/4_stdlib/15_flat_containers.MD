# 15. Плоские контейнеры

## Суть

Плоский контейнер хранит данные в последовательном буфере, но использует их как ассоциативную структуру.

Идея: отсортированный `std::vector` иногда быстрее дерева из-за хорошей локальности памяти.

В C++23 появились `std::flat_set` и `std::flat_map`.

До этого похожее поведение часто делают вручную через `std::vector` + алгоритмы.

## Пример 1: set на vector

```cpp
#include <algorithm>
#include <vector>

std::vector<int> values{10, 30, 20};

std::sort(values.begin(), values.end());
values.erase(std::unique(values.begin(), values.end()), values.end());
```

Получается отсортированный набор уникальных значений.

## Пример 2: поиск

```cpp
bool contains(const std::vector<int>& values, int x) {
    return std::binary_search(values.begin(), values.end(), x);
}
```

Поиск по отсортированному вектору стоит `O(log n)`.

## Пример 3: вставка

```cpp
void insert_unique(std::vector<int>& values, int x) {
    auto it = std::lower_bound(values.begin(), values.end(), x);

    if (it == values.end() || *it != x) {
        values.insert(it, x);
    }
}
```

Поиск позиции быстрый, но сама вставка может сдвигать элементы.

## Подводные камни

## 1. Нужно сохранять сортировку

```cpp
values.push_back(5); // может сломать инвариант
```

После обычного `push_back` бинарный поиск может стать некорректным.

## 2. Вставка дорогая

Вставка в середину `vector` стоит `O(n)`.

Плоские контейнеры хороши, когда чтения больше, чем изменений.

## 3. C++23 может быть недоступен

`std::flat_map` и `std::flat_set` зависят от версии стандарта и библиотеки.

В старом окружении используют `vector` или сторонние реализации.

## 4. Инвалидация как у vector

При реаллокации старые указатели, ссылки и итераторы становятся невалидными.

## Саммари

- Плоский контейнер хранит данные подряд.
- Часто это отсортированный `vector`.
- Поиск быстрый из-за бинарного поиска и локальности памяти.
- Вставка и удаление могут быть дорогими.
- Нужно поддерживать сортировку.
- `std::flat_map` и `std::flat_set` появились в C++23.
