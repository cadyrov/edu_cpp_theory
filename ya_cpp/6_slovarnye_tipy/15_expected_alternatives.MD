# 15. Альтернативы `std::expected`

## Суть

`std::expected<T, E>` — стандартный тип C++23 для результата, который содержит либо значение `T`, либо ошибку `E`.

Если нужны отдельное хранение системной ошибки и исключения, настраиваемая реакция на неверный доступ или поддержка старых стандартов C++, можно рассмотреть Boost.Outcome. В Rust аналогичная задача решается типом `Result<T, E>`, дополненным средствами самого языка.

## Сравнение `std::expected` и Boost.Outcome

| Критерий | `std::expected<T, E>` | Boost.Outcome |
|---|---|---|
| Модель результата | значение или ошибка | значение, код ошибки и/или исключение |
| Зависимость | стандартная библиотека C++23 | Boost либо standalone Outcome |
| Тип ошибки | задаёт пользователь | часто `error_code`, настраивается |
| Передача ошибки вверх | проверки и монадические операции | проверки и `BOOST_OUTCOME_TRY` |
| Неверный доступ | стандартное поведение API | настраивается политикой |
| Расширение поведения | ограничено стандартом | политики и точки настройки |
| Сложность | ниже | выше |

Основные типы Outcome:

- `result<T, E>` — близок к `expected<T, E>`;
- `outcome<T, EC, EP>` — дополнительно хранит сведения об исключении;
- `basic_outcome<T, EC, EP, NoValuePolicy>` — позволяет явно настроить все типы и политику доступа.

`basic_outcome` нельзя считать обычным трёхвариантным `variant`: ошибка и исключение могут присутствовать одновременно.

## Пример Boost.Outcome

```cpp
#include <boost/outcome.hpp>

namespace outcome = BOOST_OUTCOME_V2_NAMESPACE;

outcome::outcome<int> Divide(int lhs, int rhs) {
    if (rhs == 0) {
        return std::make_error_code(std::errc::invalid_argument);
    }
    return lhs / rhs;
}
```

Проверка результата:

```cpp
auto result = Divide(10, 2);

if (result) {
    std::cout << result.value();
} else if (result.has_error()) {
    std::cerr << result.error().message();
} else if (result.has_exception()) {
    std::rethrow_exception(result.exception());
}
```

## Макрос `BOOST_OUTCOME_TRY`

Макрос извлекает успешное значение, а при ошибке досрочно возвращает неуспешный результат из текущей функции.

```cpp
outcome::result<int> LoadNumber() {
    BOOST_OUTCOME_TRY(text, ReadText());
    return ParseNumber(text);
}
```

Приблизительный ручной эквивалент:

```cpp
auto result = ReadText();
if (!result) {
    return result.as_failure();
}
auto text = std::move(result).value();
return ParseNumber(text);
```

Точное поведение и набор вариантов макроса зависят от версии Outcome. Макрос сокращает шаблонный код, но усложняет отладку и может скрывать перемещения объектов.

## Политики и точки настройки

`NoValuePolicy` определяет реакцию на вызов `value()`, `error()` или `exception()` в неподходящем состоянии. Это позволяет выбрать проверяемое поведение, завершение программы или собственную обработку.

Outcome также предоставляет точки настройки жизненного цикла объектов. Их API менялся между версиями, поэтому реализацию расширений нужно сверять с документацией используемой версии.

## Rust `Result<T, E>`

В Rust `Result<T, E>` встроен в стандартную модель обработки ошибок:

```rust
fn load_number() -> Result<i32, Error> {
    let text = read_text()?;
    parse_number(&text)
}
```

Оператор `?` извлекает значение или досрочно возвращает ошибку, при необходимости преобразуя её. Для явной обработки вариантов используется `match`.

| Возможность | `std::expected` | Boost.Outcome | Rust `Result` |
|---|---|---|---|
| Часть стандарта | C++23 | нет | да |
| Отдельное состояние исключения | нет | да | нет |
| Краткое распространение ошибки | монадические операции | TRY-макросы | оператор `?` |
| Сопоставление с образцом | нет общего стандартного аналога | нет | `match` |
| Настраиваемая политика доступа | нет | да | не требуется в таком виде |

В актуальном стандарте C++ нет общего аналога Rust `?` и полноценного стандартного сопоставления с образцом. Соответствующие предложения развиваются, но рассчитывать на их синтаксис в переносимом коде пока нельзя.

## Что выбрать

- Обычный результат «значение или ошибка» в C++23 — `std::expected`.
- Нужны код ошибки, исключение и настраиваемые политики — Boost.Outcome.
- Нельзя добавлять внешнюю зависимость — `std::expected` или собственный минимальный тип для старого стандарта.
- В Rust — `Result<T, E>` и оператор `?`.

## Подводные камни

- `std::expected` не заставляет проверять результат: для важных функций полезен `[[nodiscard]]`.
- `exception_ptr` переносит объект исключения, но не продолжает раскрутку исходного стека.
- `error_code` без продуманной категории и контекста может давать слишком бедную диагностику.
- TRY-макросы скрывают досрочный выход, преобразования и перемещения.
- Политики Outcome меняют последствия неверного доступа — это часть контракта функции.
- Не смешивай исключения, `error_code` и `expected` без правил преобразования между слоями.
- Не переноси синтаксис и семантику Rust в C++ буквально: `?` тесно связан с системой типов Rust.

## Саммари

`std::expected` — простой стандартный выбор для пары «результат или ошибка». Boost.Outcome сложнее, но поддерживает более богатую модель отказа и настройку поведения. Удобство Rust `Result` обеспечивается не только типом, но и языковыми средствами `?` и `match`.
