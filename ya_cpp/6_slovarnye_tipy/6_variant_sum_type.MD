# 6. Тип-сумма `std::variant`

## Суть

Тип-сумма хранит значение ровно одного типа из заранее заданного набора.

```cpp
std::variant<int, std::string> value = 42;
value = std::string{"hello"};
```

`std::variant` появился в C++17 как типобезопасная замена ручной связке `union + enum`.

Он полезен, когда:

- полный набор вариантов известен на этапе компиляции;
- типы не обязаны иметь общего базового класса;
- нужна value-семантика без динамического полиморфизма;
- состояние программы естественно выражается как «одно из нескольких».

## Почему не `void*`

`void*` не хранит информацию о фактическом типе. Ошибка в отдельном теге и неправильный `static_cast` приводят к UB.

```cpp
void Process(void* data, Type type); // тег и объект могут не совпасть
```

Компилятор не может проверить согласованность `data` и `type`, а время жизни объекта полностью контролирует программист.

## Почему не наследование

Виртуальный полиморфизм подходит для открытой иерархии с общим интерфейсом. `variant` лучше описывает закрытый набор несвязанных типов.

| Критерий | Виртуальная иерархия | `std::variant` |
|---|---|---|
| Набор типов | Можно расширять наследниками | Зафиксирован в типе |
| Хранение | Обычно через указатель/ссылку | По значению внутри `variant` |
| Диспетчеризация | Виртуальный вызов | Проверка индекса / `std::visit` |
| Связь типов | Общий базовый класс | Не требуется |
| Добавление нового варианта | Новый класс | Изменение типа `variant` и обработчиков |

## Проблемы обычного `union`

```cpp
union IntOrFloat {
    int integer;
    float real;
};
```

`union` выделяет общую память для всех полей, но не отслеживает активное поле. При работе с нетривиальными типами приходится вручную:

- создавать объект через placement new или `std::construct_at`;
- вызывать деструктор через `std::destroy_at`;
- хранить отдельный тег текущего типа;
- корректно реализовывать копирование, перемещение и исключения.

Чтение неактивного поля обычно приводит к UB. `std::variant` инкапсулирует эту логику.

## Создание `std::variant`

```cpp
#include <string>
#include <variant>

std::variant<int, float> value = 42;
value = 4.2f;
```

По умолчанию создаётся первый вариант:

```cpp
std::variant<std::string, int> value;
// хранит пустую std::string, index() == 0
```

Поэтому конструктор по умолчанию доступен, только если первый тип конструируется по умолчанию.

## Получение значения

### `std::get`

```cpp
std::variant<int, float> value = 42;

int number = std::get<int>(value);
// std::get<float>(value); // std::bad_variant_access
```

Запрос типа, которого нет в списке, — ошибка компиляции.

### `std::get_if`

```cpp
if (int* number = std::get_if<int>(&value)) {
    Use(*number);
}
```

`get_if` возвращает `nullptr`, если активен другой вариант, и не бросает исключение.

### `std::holds_alternative`

```cpp
if (std::holds_alternative<int>(value)) {
    Use(std::get<int>(value));
}
```

### `index()`

```cpp
std::size_t active = value.index();
```

Индекс полезен, когда один тип встречается несколько раз.

## Повторяющиеся типы

`variant` может содержать одинаковые типы, но доступ по типу тогда неоднозначен.

```cpp
std::variant<std::string, double, std::string> value{
    std::in_place_index<2>, "text"
};

auto& text = std::get<2>(value);
// std::get<std::string>(value); // ошибка компиляции
```

Обычно лучше использовать уникальные типы: индексный код хуже объясняет смысл состояния.

## Явное пустое состояние

`variant` всегда пытается хранить один из вариантов. Для логического состояния «ничего» добавляют `std::monostate` первым типом:

```cpp
using Result = std::variant<std::monostate, int, std::string>;

Result result; // monostate, index() == 0
```

`monostate` — обычный пустой тип, а не особое внутреннее состояние `variant`.

## Создание на месте

```cpp
using Data = std::variant<std::string, std::vector<int>, bool>;

Data data{
    std::in_place_type<std::vector<int>>,
    {1, 2, 3}
};

data.emplace<std::string>(5, 'A'); // "AAAAA"
```

Для повторяющихся типов используйте `std::in_place_index<I>` и `emplace<I>`.

## Внутреннее устройство

Концептуально `variant` содержит:

- хранилище размером не меньше самого крупного варианта;
- индекс активного типа;
- логику создания и уничтожения активного объекта.

В libstdc++ хранилище реализовано через рекурсивные `union`, но это деталь реализации, не гарантированная стандартом.

## `valueless_by_exception`

При исключении во время замены активного значения `std::variant` в редких случаях может перейти в состояние `valueless_by_exception()`.

```cpp
if (value.valueless_by_exception()) {
    // ни одна альтернатива не активна
}
```

В этом состоянии `index()` возвращает `std::variant_npos`, а `std::get` и `std::visit` бросают `std::bad_variant_access`.

## История

До C++17 типобезопасный тип-сумму широко предоставлял `boost::variant`. Более поздний `boost::variant2` спроектирован так, чтобы никогда не переходить в `valueless_by_exception`.

## Подводные камни

### 1. Первый тип определяет конструктор по умолчанию

Если он не default-constructible, добавьте `std::monostate` или явно инициализируйте другой вариант.

### 2. `std::get<T>` требует уникальный тип

При повторении `T` обращайтесь по индексу или замените одинаковые типы отдельными обёртками с говорящими именами.

### 3. `variant` может стать `valueless_by_exception`

Это не нормальное «пустое» состояние и не замена `monostate`.

### 4. Размер равен не сумме размеров

Хранилище ориентируется на самый большой вариант, но к нему добавляются индекс и выравнивание.

### 5. `variant` не заменяет любой полиморфизм

Он хорош для закрытого набора вариантов. Если новые типы должны добавляться без изменения существующего кода, виртуальный интерфейс может быть уместнее.

### 6. Ручной `union` требует полного управления временем жизни

Недостаточно добавить тег: нужны корректные деструктор, копирование, перемещение, присваивание и обработка исключений.

## Саммари

- `std::variant<Ts...>` хранит один тип из закрытого набора.
- Он безопаснее `void*` и ручного `union + enum`.
- `get` бросает при неверном активном типе, `get_if` возвращает `nullptr`.
- `holds_alternative` проверяет тип, `index()` сообщает индекс.
- `monostate` моделирует явное пустое состояние.
- Повторяющиеся типы допустимы, но требуют индексного доступа.
- `valueless_by_exception` — редкое аварийное состояние, а не обычная альтернатива.
