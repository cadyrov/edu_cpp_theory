# 8. Двойная и множественная диспетчеризация

## Суть

Обычный `std::visit` выбирает обработчик по активному типу одного `variant`. Если передать несколько вариантов, выбор зависит от комбинации их активных типов.

```cpp
std::visit(visitor, first, second);        // двойная диспетчеризация
std::visit(visitor, first, second, third); // множественная диспетчеризация
```

Это полезно для:

- операций над значениями разных типов;
- столкновений геометрических объектов;
- конечных автоматов: состояние + событие;
- интерпретаторов: левый операнд + оператор + правый операнд;
- преобразований между форматами.

## Статическая и динамическая диспетчеризация

Перегрузка обычной функции выбирается по статическим типам на этапе компиляции:

```cpp
void Export(const Shape&);
void Export(const Circle&);

void Process(Shape& shape) {
    Export(shape); // Export(const Shape&)
}
```

Виртуальный вызов учитывает динамический тип одного объекта. Двойная диспетчеризация выбирает поведение по динамическим типам сразу двух объектов.

В классическом ООП для этого используют два виртуальных вызова и Visitor. С `variant` набор типов закрыт и комбинации выбирает `std::visit` без иерархии наследования.

## Два `variant`

```cpp
template <class... Ts>
struct Overloaded : Ts... {
    using Ts::operator()...;
};

template <class... Ts>
Overloaded(Ts...) -> Overloaded<Ts...>;

using Value = std::variant<int, double, std::string>;

Value left = 24;
Value right = 42;

double result = std::visit(Overloaded{
    [](int lhs, int rhs) -> double {
        return lhs + rhs;
    },
    [](double lhs, double rhs) -> double {
        return lhs + rhs;
    },
    [](const auto&, const auto&) -> double {
        throw std::logic_error{"Unsupported combination"};
    }
}, left, right);
```

Посетитель должен быть вызываемым для каждой возможной комбинации типов. Обобщённая ветка закрывает неподдерживаемые сочетания.

## Три `variant`

Для выражения `Number Operator Number` можно посетить три токена сразу:

```cpp
using Token = std::variant<Number, Operator, Bracket>;

Token result = std::visit(Overloaded{
    [](const Number& lhs,
       Operator op,
       const Number& rhs) -> Token {
        switch (op) {
        case Operator::Plus:
            return Number{lhs.value + rhs.value};
        case Operator::Minus:
            return Number{lhs.value - rhs.value};
        }
        throw std::logic_error{"Unknown operator"};
    },
    [](const auto&, const auto&, const auto&) -> Token {
        throw std::runtime_error{"Invalid token structure"};
    }
}, first, second, third);
```

Это заменяет повторяющиеся `holds_alternative` и `get`, но не проверку смысла оператора внутри типа `Operator`.

## Количество комбинаций

Компилятор проверяет декартово произведение альтернатив:

| Первый `variant` | Второй | Третий | Комбинаций |
|---:|---:|---:|---:|
| 2 | 3 | — | 6 |
| 4 | 5 | 3 | 60 |
| 6 | 6 | 6 | 216 |

Формула:

```text
N = size(V1) × size(V2) × ... × size(Vk)
```

Рост числа комбинаций может увеличить:

- время компиляции;
- размер объектного кода;
- объём диагностик;
- сложность набора обработчиков.

Наличие общей лямбды упрощает исходный код, но компилятор всё равно обязан проверить её применимость ко всем комбинациям.

## Возвращаемый тип

У формы с выводимым результатом все комбинации должны возвращать один и тот же тип и категорию значения.

```cpp
// Ошибка: ветки возвращают int и double.
std::visit(Overloaded{
    [](int, int) { return 42; },
    [](double, double) { return 3.14; }
}, first, second);
```

Варианты решения:

```cpp
// Единый явный тип в каждой ветке.
[](int, int) -> double { return 42; }

// Или std::visit<R> начиная с C++20.
auto result = std::visit<double>(visitor, first, second);

// Или тип-сумма результатов.
using Result = std::variant<int, double, Error>;
```

В `std::visit<R>` результат каждой ветки должен быть приводим к `R`.

## Частично обобщённые комбинации

У `std::visit` нет отдельного синтаксиса pattern matching, но обобщённые и ограниченные лямбды позволяют описывать группы сочетаний:

```cpp
std::visit(Overloaded{
    [](const Number& lhs,
       const auto& operation,
       const Number& rhs)
        requires Operation<decltype(operation)> {
        // Любая поддерживаемая операция между Number.
    },
    [](const auto&, const auto&, const auto&) {
        throw std::runtime_error{"Invalid expression"};
    }
}, first, second, third);
```

Следите за пересечением перегрузок: слишком общие лямбды могут создать неоднозначность или перехватить комбинацию раньше ожидаемого.

## Производительность

Стандарт не задаёт конкретную реализацию `std::visit`. Библиотека может использовать таблицу функций, `switch` или их комбинацию.

На практике важны:

- число альтернатив и посещаемых вариантов;
- частота вызова;
- возможность встраивания обработчиков;
- расположение данных в памяти;
- настройки оптимизации.

В горячем цикле сравнивайте решения измерениями. Отсутствие виртуальных функций само по себе не гарантирует ускорение.

## Когда выбрать другой подход

Рассмотрите декомпозицию, виртуальный интерфейс или таблицу операций, если:

- одновременно посещается много вариантов;
- каждый `variant` содержит много альтернатив;
- набор типов часто меняется;
- большинство комбинаций недопустимо;
- логика сочетаний образует большую разреженную матрицу.

## Подводные камни

### 1. Catch-all скрывает новые комбинации

Общая лямбда сохраняет компилируемость после добавления типа, но новая комбинация может начать падать только во время выполнения.

### 2. Порядок аргументов важен

Обработчики `(Circle, Rectangle)` и `(Rectangle, Circle)` — разные комбинации. Если операция симметрична, явно переиспользуйте реализацию.

### 3. Все варианты должны быть валидны

Если хотя бы один аргумент находится в `valueless_by_exception`, `std::visit` бросает `std::bad_variant_access`.

### 4. Одинаковый тип результата обязателен

Не рассчитывайте на автоматический поиск общего типа для обычного `std::visit`.

### 5. Добавление альтернативы размножает комбинации

Новый тип затрагивает произведение всех остальных наборов, поэтому утверждение «добавить тип без изменения кода» справедливо только при осознанной общей ветке.

### 6. Извлечение токенов всё ещё требует проверки границ

`visit` проверяет типовую комбинацию, но не защищает от пустого стека, неверного порядка чтения или несбалансированного выражения.

## Саммари

- `std::visit` принимает несколько `variant` и выбирает обработчик по комбинации активных типов.
- Два варианта дают двойную, три и более — множественную диспетчеризацию.
- Посетитель должен поддерживать декартово произведение альтернатив.
- Число комбинаций равно произведению числа типов во всех вариантах.
- Обычный `visit` требует одинакового результата всех веток; `visit<R>` задаёт его явно.
- Catch-all удобен, но переносит часть ошибок с этапа компиляции на этап выполнения.
- При большом числе типов и аргументов важны декомпозиция и измерение производительности.
