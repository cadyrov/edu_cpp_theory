# 12. Хранение произвольных данных: `std::any`

## Суть

`std::any` — владеющий type-erased контейнер из C++17. Он хранит одно значение произвольного копируемого типа либо остаётся пустым.

```cpp
#include <any>

std::any value = 42;
value = 3.14;
value = std::string{"hello"};
```

В отличие от `std::variant`, список допустимых типов не входит в объявление контейнера.

`std::any` предоставляет универсальное хранение, но не общий интерфейс поведения: чтобы использовать объект, нужно знать его точный тип и выполнить `any_cast`.

## Создание и состояние

```cpp
std::any empty;
std::any number{42};

if (number.has_value()) {
    // значение есть
}

number.reset();
number = std::string{"text"};
```

Создание на месте:

```cpp
std::any values = std::make_any<std::vector<int>>(
    std::initializer_list<int>{1, 2, 3}
);

values.emplace<std::string>(5, 'A'); // "AAAAA"
```

Хранимый тип после decay должен быть `CopyConstructible`.

## `std::any_cast`

### Получение копии

```cpp
std::any value = 42;
int copy = std::any_cast<int>(value);
```

### Получение ссылки

```cpp
int& reference = std::any_cast<int&>(value);
reference = 100;
```

### Проверка через указатель

```cpp
if (int* pointer = std::any_cast<int>(&value)) {
    Use(*pointer);
}
```

Поведение при несовпадении:

| Форма | Ошибка типа |
|---|---|
| `std::any_cast<T>(any)` | Бросает `std::bad_any_cast` |
| `std::any_cast<T>(&any)` | Возвращает `nullptr` |

В ветвящемся коде указательная форма часто проще и не использует исключения.

## Требуется точное совпадение типа

`any_cast` не выполняет обычные преобразования:

```cpp
std::any value = 42;

std::any_cast<int>(value);          // корректно
// std::any_cast<long>(value);      // bad_any_cast
// std::any_cast<double>(value);    // bad_any_cast
```

То же относится к базовым классам:

```cpp
std::any value = Derived{};
// std::any_cast<Base>(value); // тип внутри — Derived, не Base
```

Тип хранения является частью неявного runtime-контракта между записывающим и читающим кодом.

## Информация о типе

```cpp
if (value.type() == typeid(int)) {
    Use(std::any_cast<int>(value));
}
```

Для пустого `any` метод `type()` возвращает `typeid(void)`.

`type().name()` предназначен главным образом для диагностики: строка implementation-defined, может быть нечитаемой и различаться между компиляторами.

## Разнородный контейнер

```cpp
std::vector<std::any> objects;
objects.emplace_back(42);
objects.emplace_back(std::string{"abc"});
objects.emplace_back(2.5);
```

Извлекающий код всё равно должен знать поддерживаемые типы:

```cpp
for (const std::any& object : objects) {
    if (const int* value = std::any_cast<int>(&object)) {
        Print(*value);
    } else if (const auto* text =
                   std::any_cast<std::string>(&object)) {
        Print(*text);
    }
}
```

Если этот список закрыт и известен заранее, `std::variant` обычно выражает его лучше.

## Как устроен `std::any`

Концептуальная реализация содержит:

- type-erased хранилище объекта;
- операцию уничтожения;
- операцию копирования;
- информацию о фактическом типе;
- возможно, внутренний буфер для небольшого объекта.

Упрощённая схема:

```cpp
struct Placeholder {
    virtual const std::type_info& Type() const = 0;
    virtual std::unique_ptr<Placeholder> Clone() const = 0;
    virtual ~Placeholder() = default;
};

template <typename T>
struct Holder final : Placeholder {
    explicit Holder(T value)
        : value_(std::move(value)) {}

    const std::type_info& Type() const override {
        return typeid(T);
    }

    std::unique_ptr<Placeholder> Clone() const override {
        return std::make_unique<Holder>(*this);
    }

    T value_;
};
```

Реальная реализация стандартной библиотеки не обязана использовать виртуальные классы.

## Small-object optimization

Многие реализации хранят небольшой объект прямо внутри `any`, а крупный — в динамической памяти.

Точный размер буфера и условия SBO не стандартизованы. Они могут зависеть от:

- размера и выравнивания типа;
- свойств копирования и перемещения;
- реализации стандартной библиотеки.

Не полагайтесь на конкретный порог вроде 16 или 24 байт в переносимом коде.

## Где `std::any` уместен

- расширяемые параметры плагинов;
- метаданные на границе независимых подсистем;
- прототипы с ещё не определённой схемой;
- heterogeneous property bag;
- инфраструктура, где множество типов действительно открыто.

```cpp
using Properties = std::unordered_map<std::string, std::any>;

Properties properties;
properties["port"] = 8080;
properties["user"] = std::string{"admin"};
```

Даже здесь полезно централизовать ключи и функции чтения, чтобы не размазывать строки и `any_cast` по проекту.

## Сравнение инструментов

| Задача | Предпочтительный инструмент |
|---|---|
| Один тип, известный при инстанцировании | Шаблон |
| Закрытый набор альтернатив | `std::variant` |
| Объекты реализуют общий виртуальный интерфейс | Наследование |
| Открытый набор типов с фиксированным поведением | Пользовательский type erasure |
| Открытый набор типов без общего поведения | `std::any` |
| Может отсутствовать одно конкретное значение | `std::optional<T>` |

## `any`, `variant` и `void*`

| Критерий | `std::any` | `std::variant<Ts...>` | `void*` |
|---|---|---|---|
| Набор типов | Открытый | Закрытый | Не описан |
| Владение значением | Да | Да | Сам по себе не выражает |
| Автоматическое уничтожение | Да | Да | Нет информации |
| Проверка типа | Runtime через `any_cast` | Runtime по активной альтернативе | Вручную |
| Обработка всех вариантов | Не проверяется | Проверяется через `visit` | Не проверяется |
| Требование копируемости значения | Да | Зависит от операций variant | Нет встроенного контракта |

## Подводные камни

### 1. Ошибка может обнаружиться далеко от записи

Один модуль сохраняет `int`, другой ожидает `long` и получает `bad_any_cast`. Создавайте типизированные функции доступа.

### 2. Извлечение по значению копирует

```cpp
auto data = std::any_cast<BigData>(value); // копия
```

Используйте `BigData&` или `const BigData&`, если копия не нужна.

### 3. Move-only тип сохранить нельзя

`std::unique_ptr<T>` и другие некопируемые значения напрямую не подходят. Обёртка в `shared_ptr` меняет семантику владения и должна быть осознанным решением.

### 4. Нет встроенных `visit`, сравнения и хеширования содержимого

`any` не знает требуемых операций над произвольным типом. Их нужно организовать отдельно.

### 5. `type().name()` нестабилен

Не используйте его как формат сериализации, постоянный идентификатор или пользовательское имя типа.

### 6. Открытый набор типов не означает отсутствие схемы

Читающий код всё равно должен понимать тип и смысл значения. Без реестра или протокола `any` лишь переносит проблему в runtime.

### 7. Самописный `any` требует сильной гарантии исключений

При присваивании сначала создайте новое содержимое, затем замените старое. Схема `delete old; new Holder(...)` оставляет объект повреждённым, если аллокация или копирование бросит.

### 8. `any` не всегда лучший тип для JSON

Если JSON-модель известна (`null`, `bool`, число, строка, массив, объект), рекурсивный `variant` обычно точнее описывает данные.

## Саммари

- `std::any` хранит одно значение произвольного копируемого типа.
- Пустота проверяется через `has_value`, очистка выполняется через `reset`.
- Значение извлекается только через точный тип в `any_cast`.
- Значимая форма `any_cast` бросает, указательная возвращает `nullptr`.
- `std::any` владеет объектом и управляет его временем жизни.
- Для закрытого набора типов предпочтительнее `std::variant`.
- Используйте `any` только при действительно открытом множестве типов и явном runtime-контракте.
