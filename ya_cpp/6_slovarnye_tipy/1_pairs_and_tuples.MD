# 1. Словарные типы. Пары и кортежи

## Суть

Словарные типы выражают распространённые структуры данных и служат строительными блоками программы. Если стандартный тип подходит, обычно лучше выбрать его: такой код проще читать и объединять с другими библиотеками.

`std::pair<T, U>` хранит два значения, а `std::tuple<Ts...>` — произвольное число значений разных типов.

Их удобно использовать:

- для возврата нескольких независимых результатов;
- в обобщённом коде, где состав значений определяется типами;
- на раннем этапе проектирования, пока отдельная структура избыточна.

Если значения образуют самостоятельную сущность, лучше создать структуру с говорящими именами полей.

## `std::pair`

У пары два публичных поля: `first` и `second`.

```cpp
#include <string>
#include <utility>

std::pair<std::string, bool> LoadName() {
    return {"Alice", true};
}

if (auto [name, ok] = LoadName(); ok) {
    // используем name
}
```

С C++17 типы можно вывести автоматически:

```cpp
std::pair value{42, 3.14}; // std::pair<int, double>
```

Доступ возможен через `first`, `second` или `std::get`:

```cpp
auto first = value.first;
auto second = std::get<1>(value);
```

## `std::tuple`

Кортеж хранит любое число значений. Доступ выполняется через `std::get` по индексу или уникальному типу.

```cpp
#include <string>
#include <tuple>

std::tuple user{7, std::string{"Bob"}, 4.5};

auto id = std::get<0>(user);
auto rating = std::get<double>(user);
auto [userId, name, userRating] = user;
```

`std::apply` вызывает функцию, передавая элементы кортежа как аргументы:

```cpp
int Sum(int a, int b) {
    return a + b;
}

auto args = std::tuple{2, 3};
int result = std::apply(Sum, args); // 5
```

## Подводные камни

### 1. Безымянные поля ухудшают читаемость

`first`, `second` и числовые индексы не объясняют смысл данных. Для связанных значений лучше структура:

```cpp
struct User {
    int id;
    std::string name;
};
```

### 2. У `pair` нет `operator[]`

```cpp
std::pair p{10, 20};
// p[0];              // ошибка
auto value = p.first; // корректно
```

### 3. `std::get<Type>` требует уникальный тип

```cpp
std::tuple<int, int, double> values{1, 2, 3.0};
// std::get<int>(values); // ошибка: int встречается дважды
std::get<1>(values);      // корректно
```

Неверный индекс `std::get<N>` также приводит к ошибке компиляции.

### 4. Структурная привязка по умолчанию копирует

```cpp
auto [id, name] = pair;        // копии
auto& [idRef, nameRef] = pair; // ссылки
const auto& [a, b] = pair;     // константные ссылки
```

### 5. Не нужно писать `std::move` для временного объекта

```cpp
return std::pair{LargeObject{}, LargeObject{}};
```

Но при сборке пары из именованных локальных объектов перемещение может понадобиться:

```cpp
return std::pair{std::move(first), std::move(second)};
```

## Саммари

- `std::pair` хранит два значения, `std::tuple` — произвольное число.
- С C++17 типы удобно выводятся автоматически, а элементы распаковываются структурными привязками.
- `std::get<N>` обращается по индексу, `std::get<T>` — по уникальному типу.
- `std::apply` передаёт элементы кортежа в функцию.
- Для связанных данных предпочтительнее структура с именованными полями.
