# 4. Как выразить семантику значения в типе

## Суть

Тип должен показывать две вещи:

1. Может ли значение отсутствовать?
2. Кто управляет временем жизни объекта?

Основные варианты:

- `std::optional<T>` — необязательное владеющее значение;
- `T*` — необязательный невладеющий доступ с семантикой указателя;
- `T&` — обязательная непереназначаемая ссылка;
- `std::reference_wrapper<T>` — обязательная копируемая ссылка;
- `gsl::not_null<T*>` — невладеющий указатель, который не должен быть `nullptr`.

## `T*` и `std::optional<T>`

Оба типа могут выражать отсутствие объекта, но имеют разную семантику.

| Критерий | `T*` | `std::optional<T>` |
|---|---|---|
| Может быть пустым | Да, `nullptr` | Да, `std::nullopt` |
| Владеет `T` | Обычно нет | Да |
| Где находится `T` | Отдельно от указателя: стек, куча, static storage и т. д. | Внутри самого `optional` |
| Время жизни `T` | Контролирует другой код | Контролирует `optional` |
| Смена адресуемого объекта | Возможна | Неприменимо: хранится значение |
| Доступ | `*ptr`, `ptr->` после проверки | `value()`, `*opt`, `opt->` |
| Работа с C API | Естественная | Обычно неудобна |
| Размер | Обычно один машинный адрес | `sizeof(T)` плюс флаг и выравнивание |

```cpp
std::optional<User> FindUser(int id); // возвращает и владеет результатом
User* FindCachedUser(int id);         // невладеющий доступ, возможен nullptr
```

Используйте `optional`, если значение принадлежит текущему объекту или возвращается по значению. Сырой указатель подходит для невладеющего взаимодействия с внешним кодом и C API.

## `T&` и `std::reference_wrapper<T>`

Обычная ссылка не может быть пустой и после инициализации всегда обозначает тот же объект.

```cpp
int first = 10;
int second = 20;

int& ref = first;
ref = second; // first становится равен 20; ссылка не переназначается
```

`std::reference_wrapper<T>` тоже не имеет пустого состояния, но его можно копировать и переназначать на другой объект.

```cpp
#include <functional>

int first = 10;
int second = 20;

std::reference_wrapper<int> ref = first;
ref = second; // теперь ref обозначает second
ref.get() = 30;
```

### Сравнение ссылочных типов

| Критерий | `T&` | `std::reference_wrapper<T>` |
|---|---|---|
| Пустое состояние | Нет | Нет |
| Владеет объектом | Нет | Нет |
| Копируется как отдельный объект | Нет | Да |
| Можно переназначить | Нет | Да |
| Можно хранить в стандартном контейнере | Нет | Да |
| Доступ к объекту | Напрямую | Неявное преобразование или `.get()` |

`reference_wrapper` позволяет создать контейнер ссылок:

```cpp
std::list<int> values{1, 2, 3};
std::vector<std::reference_wrapper<int>> refs(
    values.begin(), values.end()
);

refs[0].get() = 10; // меняется первый элемент values
```

Для создания обёрток удобно использовать `std::ref` и `std::cref`.

## `gsl::not_null<T*>`

`gsl::not_null` выражает контракт: указатель обязан быть ненулевым.

```cpp
#include <gsl/gsl>

void Preprocess(gsl::not_null<Image*> image) {
    image->Prepare();
}

// Preprocess(nullptr); // ошибка компиляции
```

Граница с C API всё равно требует проверки:

```cpp
gsl::not_null<Image*> CurrentImage() {
    Image* image = lib_api_get_current_image();
    if (image == nullptr) {
        throw std::runtime_error{"Image is unavailable"};
    }
    return image;
}
```

После проверки внутренний код принимает `not_null` и не повторяет `if (ptr)` в каждой функции.

### Что гарантирует `not_null`

- явно документирует запрет `nullptr` в интерфейсе;
- не позволяет напрямую передать литерал `nullptr`;
- сохраняет семантику указателя и не владеет объектом;
- не гарантирует время жизни объекта;
- не делает висячий указатель безопасным.

## Полное сравнение

| Тип | Может отсутствовать | Владение | Переназначение | Основное применение |
|---|---:|---:|---:|---|
| `std::optional<T>` | Да | Да | Заменяется хранимое значение | Необязательное значение, ленивое создание |
| `T*` | Да | Нет | Да | C API, необязательный внешний объект |
| `gsl::not_null<T*>` | Нет | Нет | Да | Обязательный указатель в интерфейсе |
| `std::reference_wrapper<T>` | Нет | Нет | Да | Ссылка в контейнере или копируемом объекте |
| `T&` | Нет | Нет | Нет | Обязательный параметр или один раз привязанная ссылка |

## Как выбрать тип

| Ситуация | Владение | Наличие | Рекомендуемый тип |
|---|---|---|---|
| Значение может отсутствовать, временем жизни управляете вы | Владеете | Необязательно | `std::optional<T>` |
| Внешний объект может отсутствовать | Не владеете | Возможен `nullptr` | `T*` |
| Нужна обязательная семантика указателя | Не владеете | Всегда есть | `gsl::not_null<T*>` |
| Нужна обязательная копируемая ссылка или контейнер ссылок | Не владеете | Всегда есть | `std::reference_wrapper<T>` |
| Объект задаётся один раз и не переназначается | Не владеете | Всегда есть | `T&` |

## Подводные камни

### 1. Ненулевой не означает живой

`T&`, `reference_wrapper` и `not_null` становятся висячими, если исходный объект уничтожен или перемещён так, что ссылка инвалидирована.

### 2. `reference_wrapper` не владеет объектом

Контейнер обёрток не продлевает жизнь элементов. Особенно опасно сохранять ссылки на временные и элементы контейнеров, которые могут быть инвалидированы.

### 3. `not_null` не заменяет умные указатели

Он описывает ненулевой доступ, а не владение. Для владения используйте `std::unique_ptr` или `std::shared_ptr` с подходящим контрактом.

### 4. Не полагайтесь на `not_null` как на проверку внешнего указателя

Сырой указатель, полученный во время выполнения, сначала нужно проверить. Точное поведение при нарушении контракта зависит от реализации GSL и её настроек.

### 5. `not_null` обычно запрещает арифметику указателей

Он предназначен для ссылки на объект, а не для обхода массива. Для диапазона лучше передавать `std::span<T>`.

### 6. Учитывайте `const`

`std::reference_wrapper<const T>` и `gsl::not_null<const T*>` запрещают изменение объекта через обёртку.

## Саммари

- `optional<T>` — необязательное владеющее значение.
- `T*` — необязательный невладеющий доступ.
- `not_null<T*>` — обязательный невладеющий указатель.
- `reference_wrapper<T>` — обязательная копируемая и переназначаемая ссылка.
- `T&` — обязательная ссылка без переназначения.
- Ни один невладеющий тип не контролирует время жизни объекта.
