# 9. Точки настройки

## Суть

Точка настройки (`customization point`) позволяет библиотеке выполнить операцию для пользовательского типа без наследования от библиотечного класса.

Основные классические способы настройки:

- специализация разрешённого шаблона стандартной библиотеки;
- функция в пространстве имён пользовательского типа, найденная через ADL.

## Специализация шаблона

Для использования пользовательского ключа в `std::unordered_map` можно специализировать `std::hash`:

```cpp
struct UserId {
    int value;

    friend bool operator==(UserId, UserId) = default;
};

template <>
struct std::hash<UserId> {
    std::size_t operator()(UserId id) const noexcept {
        return std::hash<int>{}(id.value);
    }
};
```

```cpp
std::unordered_map<UserId, std::string> users;
```

Другой пример — специализация `std::formatter`, которая добавляет поддержку пользовательского типа в `std::format` и `std::print`.

Добавлять свои объявления в `namespace std` обычно запрещено. Делать это можно только в случаях, явно разрешённых стандартом, и только для подходящих пользовательских типов.

## Настройка через ADL

ADL (`argument-dependent lookup`) ищет функцию не только в текущей области, но и в пространствах имён типов её аргументов.

```cpp
namespace app {

struct Buffer {
    std::vector<int> data;

    friend void swap(Buffer& left, Buffer& right) noexcept {
        using std::swap;
        swap(left.data, right.data);
    }
};

}  // namespace app
```

Функция `swap` находится через ADL, потому что аргументы имеют тип `app::Buffer`.

## Двухшаговый вызов `swap`

В обобщённом коде используется идиома:

```cpp
template <class T>
void exchange_values(T& left, T& right) {
    using std::swap;
    swap(left, right);
}
```

Сначала в набор кандидатов добавляется стандартный `std::swap`. Затем неквалифицированный вызов позволяет ADL найти специализированную функцию рядом с пользовательским типом.

Прямой вызов `std::swap(left, right)` отключил бы поиск пользовательской перегрузки через ADL.

## Hidden friend

Функцию можно определить другом внутри класса:

```cpp
struct Point {
    int x;
    int y;

    friend void swap(Point& left, Point& right) noexcept {
        using std::swap;
        swap(left.x, right.x);
        swap(left.y, right.y);
    }
};
```

Такой `hidden friend` обычно находится только через ADL. Это удерживает операцию рядом с типом и не засоряет обычный поиск имён.

## `begin` и `end`

Пользовательский тип можно сделать диапазоном с помощью методов:

```cpp
struct Data {
    std::array<int, 3> values{1, 2, 3};

    auto begin() { return values.begin(); }
    auto end() { return values.end(); }
};

for (int value : Data{}) {
    // 1, 2, 3
}
```

Также свободные `begin` и `end` можно определить в том же пространстве имён, что и пользовательский тип, чтобы они находились через ADL.

## Недостатки классических точек настройки

- специализация требует знания правил работы с `namespace std`;
- свободная перегрузка может случайно участвовать в ADL;
- для `swap` нужен двухшаговый вызов;
- корректность результата найденной функции часто проверяется слишком поздно;
- ошибки шаблонного кода могут быть сложными для чтения.

В ranges эти проблемы решают объекты точек настройки (`CPO`), которые объединяют поиск операции и проверку ограничений.

## Подводные камни

### 1. Функция должна находиться рядом с типом

Если `swap(app::Type&, app::Type&)` объявить в глобальном пространстве, ADL для типа из `app` её не найдёт.

### 2. Не перегружай функции в `std`

Пользовательский `swap` определяют рядом со своим типом, а не добавляют перегрузку в `namespace std`.

### 3. `std::hash` требует равенства

Если два ключа равны, их хеши обязаны совпадать. Иначе поведение хеш-контейнера будет некорректным.

### 4. `noexcept` важен для `swap`

Контейнеры и алгоритмы могут выбирать более эффективный путь, если перемещение и обмен не бросают исключения.

### 5. Методы `begin` и `end` должны описывать один диапазон

Возвращаемые итератор и ограничитель должны быть совместимы и иметь корректное время жизни.

## Саммари

- Точки настройки адаптируют пользовательские типы к библиотечным операциям.
- `std::hash` и `std::formatter` настраиваются разрешёнными специализациями.
- Свободные функции вроде `swap` находятся через ADL.
- В обобщённом коде `swap` вызывают через двухшаговую идиому.
- Hidden friend удобно размещает операцию рядом с типом.
- Классические точки настройки имеют недостатки, которые ranges решает через CPO.
