# 1. Зачем появилась библиотека диапазонов

## Суть

Классические STL-алгоритмы работают с парами итераторов. Это многословно, а цепочки операций часто требуют промежуточных контейнеров и лишних проходов.

Библиотека `ranges` появилась в C++20. Она позволяет:

- передавать алгоритму диапазон целиком;
- собирать преобразования в ленивый конвейер;
- отделять итератор от ограничителя конца (`sentinel`);
- указывать поле для сравнения через проекцию.

## Диапазон вместо пары итераторов

```cpp
#include <algorithm>
#include <ranges>
#include <vector>

std::vector<int> values{1, 2, 3, 4};

auto oldIt = std::find(values.begin(), values.end(), 3);
auto newIt = std::ranges::find(values, 3);
```

Диапазон — объект, для которого можно получить начало и конец. Это не обязательно контейнер.

## Ленивый конвейер

```cpp
std::vector<int> values{1, 2, 3, 4, 5, 6};

auto result = values
    | std::views::filter([](int x) { return x % 2 == 0; })
    | std::views::transform([](int x) { return x * 100; })
    | std::views::take(2);

for (int x : result) {
    // 200, 400
}
```

`view` не хранит готовый результат. Элементы вычисляются по мере обхода, поэтому не нужны промежуточные векторы и обработка может остановиться после двух значений.

## Проекции

```cpp
struct Player {
    int score;
};

std::vector<Player> players{{30}, {10}, {20}};
std::ranges::sort(players, {}, &Player::score);
```

Проекция `&Player::score` сообщает, какое поле сравнивать. Не нужно писать компаратор с двумя аргументами.

## Sentinel

В классических алгоритмах `begin` и `end` обычно должны иметь один тип итератора. В ranges конец может обозначаться отдельным типом — `sentinel`, которому достаточно уметь сравниваться с итератором.

Это удобно для потоков и последовательностей без заранее известного конца. Для бесконечных диапазонов существует `std::unreachable_sentinel`.

## Подводные камни

### 1. View вычисляется лениво

Ошибки и побочные эффекты внутри `filter` или `transform` возникают не при создании view, а при его обходе.

### 2. View часто ссылается на исходные данные

Исходный объект должен продолжать существовать, пока используется view. Изменение контейнера может также инвалидировать его итераторы.

### 3. Повторный обход может повторить вычисления

View обычно не кеширует результаты. Дорогой `transform` может выполниться заново при следующем проходе.

### 4. Не все алгоритмы ленивые

`std::ranges::sort`, `find` и другие ranges-алгоритмы выполняются сразу. Ленивость дают главным образом `std::views`.

### 5. Несовместимые итераторы всё ещё опасны

Ranges уменьшают вероятность передать начало и конец разных контейнеров, но не отменяют правила времени жизни и инвалидации итераторов.

## Саммари

- `std::ranges` делает интерфейсы алгоритмов короче и безопаснее.
- `std::views` строит ленивые цепочки без промежуточных контейнеров.
- `sentinel` позволяет типу конца отличаться от типа итератора.
- Проекции заменяют многословные компараторы для полей объектов.
- View обычно не владеет данными и не кеширует вычисления.
