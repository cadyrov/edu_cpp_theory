# 10. CPO и алгоритмические объекты

## Суть

В ranges многие имена обозначают не функции, а глобальные `constexpr`-объекты с `operator()`.

Есть два близких механизма:

- CPO (`customization point object`) вызывает настраиваемую операцию для пользовательского типа;
- алгоритмический функциональный объект представляет ranges-алгоритм.

```cpp
std::ranges::swap(left, right);   // CPO
std::ranges::find(values, 42);    // алгоритмический объект
```

Оба выглядят как вызовы функций, но `swap` и `find` здесь являются объектами.

## Объект точки настройки

Упрощённая схема CPO:

```cpp
struct operation_fn {
    template <class T>
    constexpr auto operator()(T&& value) const
        requires /* требования */
    {
        // выбор подходящего способа выполнить операцию
    }
};

inline constexpr operation_fn operation{};
```

Единый `operator()` позволяет:

- скрыть внутренний ADL;
- проверить аргументы концептами;
- проверить результат найденной операции;
- выбрать один из нескольких способов выполнения;
- получать одинаковое поведение независимо от окружения вызова.

Пользователь вызывает CPO напрямую, без двухшаговой идиомы:

```cpp
std::ranges::swap(left, right);
```

## Стандартные CPO

Примеры объектов точек настройки:

- `std::ranges::begin`, `end`, `rbegin`, `rend`;
- `std::ranges::size`, `empty`, `data`;
- `std::ranges::swap`;
- `std::ranges::iter_move`, `iter_swap`;
- `std::strong_order`, `weak_order`, `partial_order`.

Например, `std::ranges::begin(range)` выбирает допустимый способ получить итератор и проверяет, что результат действительно удовлетворяет требованиям итератора.

## Алгоритмические функциональные объекты

Ranges-алгоритмы тоже реализованы как объекты:

```cpp
struct find_fn {
    template <std::input_iterator I,
              std::sentinel_for<I> S,
              class T>
    constexpr I operator()(I first, S last, const T& value) const;

    template <std::ranges::input_range R, class T>
    constexpr auto operator()(R&& range, const T& value) const;
};

inline constexpr find_fn find{};
```

Один объект может иметь перегрузки для пары `iterator + sentinel` и для диапазона целиком.

## Зачем алгоритмы сделаны объектами

Классические алгоритмы — функции:

```cpp
std::copy(first, last, destination);
```

Если бы `std::ranges::copy` тоже был функцией, неквалифицированный вызов мог бы через ADL собрать классическую, диапазонную и пользовательские перегрузки в один набор кандидатов.

Объект с именем `std::ranges::copy` не участвует в ADL как функция. Это предотвращает случайный выбор другой реализации.

```cpp
auto result = std::ranges::copy(source, destination.begin());
```

Кроме того, ranges-алгоритмы используют концепты и обычно возвращают больше полезной информации:

```cpp
auto [inputEnd, outputEnd] = std::ranges::copy(
    source,
    destination.begin()
);
```

## CPO и алгоритмический объект

| Свойство | CPO | Алгоритмический объект |
|---|---|---|
| Цель | Настроить операцию для типа | Выполнить алгоритм |
| Пользовательская реализация | Может находиться внутренним ADL | Не выбирается через ADL |
| Проверка концептами | Да | Да |
| Реализация | `constexpr`-объект с `operator()` | `constexpr`-объект с `operator()` |

## Ниблоиды

«Ниблоид» — неформальный термин в честь Эрика Ниблера.

В широком смысле им называют CPO и алгоритмические объекты ranges, в узком — только алгоритмические функциональные объекты.

## Подводные камни

### 1. CPO нельзя перегрузить как обычную функцию

Например, пользователь не добавляет перегрузку `std::ranges::swap`. Он определяет поддерживаемую операцию рядом со своим типом, а CPO находит её по установленным правилам.

### 2. CPO и AFO похожи только формой

CPO специально ищет пользовательскую настройку. Ranges-алгоритм, наоборот, изолирован от конкурирующих функций ADL.

### 3. Не полагайся на упрощённую реализацию CPO

Реальные стандартные объекты имеют строгий порядок выбора, ограничения и защиту от рекурсивного поиска собственного имени.

### 4. Неквалифицированный вызов может быть неочевидным

Для ясности обычно пиши полное имя: `std::ranges::copy`, `std::ranges::find`, `std::ranges::swap`.

### 5. Ошибка концепта всё ещё может быть объёмной

Диагностика обычно точнее, чем у старых алгоритмов, но сложные цепочки ограничений требуют чтения первого невыполненного требования.

## Саммари

- CPO — объект, через который безопасно настраивают операции для типов.
- CPO скрывает ADL и проверяет требования в одном месте.
- Ranges-алгоритмы реализованы как функциональные объекты.
- Это защищает их от конфликтов с функциями, найденными через ADL.
- CPO и алгоритмические объекты похожи реализацией, но различаются назначением.
- «Ниблоид» — неформальное название этих объектов.
