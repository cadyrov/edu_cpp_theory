# 13. Критика ranges и библиотека Flux

## Суть

`std::ranges` делает обработку данных выразительной, но ленивые view имеют цену:

- некоторые отображения кешируют состояние;
- `const view` не означает `const` для исходных данных;
- преобразования могут вычисляться повторно;
- глубокие цепочки создают сложные вложенные итераторы;
- невладеющие view могут содержать висячие ссылки.

Flux — сторонняя библиотека последовательностей, которая вместо автономных итераторов использует курсоры вместе с объектом последовательности.

## Кеширование `begin()`

`filter_view::begin()` ищет первый подходящий элемент. Без кеша каждый вызов мог бы стоить `O(N)`, поэтому отображение запоминает найденную позицию.

```cpp
std::vector<int> values{64, 45, 3, 12};

auto filtered = values | std::views::filter([](int value) {
    return value < 42;
});
```

После начала обхода изменение исходных элементов может сделать кеш несогласованным с предикатом. Особенно опасно менять элемент так, чтобы результат предиката для него изменился.

Практический приём — не хранить view дольше необходимого:

```cpp
for (int value : values | std::views::filter(predicate)) {
    // ...
}
```

Кеширующее отображение также может изменять внутреннее состояние при первом чтении. Одновременный первый обход одного объекта view из нескольких потоков требует синхронизации.

## Константность отображений

`const` у view часто относится к самой обёртке, а не к данным:

```cpp
std::vector<int> values{1, 2, 3};
const auto view = values | std::views::all;

view[0] = 42; // может изменять values
```

Это похоже на константный указатель: сам указатель менять нельзя, но доступные через него данные могут оставаться изменяемыми.

Чтобы запретить изменение элементов, используй `std::views::as_const` из C++23:

```cpp
auto readonly = values | std::views::as_const;
// readonly[0] = 42; // ошибка компиляции
```

`const auto&` при обходе `zip` или `enumerate` тоже не гарантирует неизменность исходных элементов, потому что tuple может хранить изменяемые ссылки.

## TPOIASI

TPOIASI — неформальное название проблемы повторных вычислений при инкременте «умного» итератора.

```cpp
auto result = values
    | std::views::transform(expensiveTransform)
    | std::views::filter(predicate);
```

Фильтр разыменовывает transform-итератор, чтобы проверить предикат. Затем прошедший элемент разыменовывается потребителем ещё раз. Поэтому `expensiveTransform` может выполниться повторно.

Варианты решения:

```cpp
// 1. Фильтровать исходные данные раньше, если условие можно переписать.
auto result = values
    | std::views::filter(sourcePredicate)
    | std::views::transform(expensiveTransform);

// 2. Материализовать дорогой результат.
auto transformed = values
    | std::views::transform(expensiveTransform)
    | std::ranges::to<std::vector>();
```

В C++26 для кеширования последнего вычисленного элемента предназначен `std::views::cache_latest`.

## Проекции не обязаны кешироваться

Алгоритм может вызвать проекцию для одного элемента несколько раз:

```cpp
auto it = std::ranges::min_element(
    people,
    {},
    expensiveProjection
);
```

Обязательная мемоизация невозможна без компромиссов:

- результат может быть тяжёлым или неперемещаемым;
- проекция может возвращать ссылку;
- сортировка переставляет элементы;
- кеш потребует памяти;
- побочные эффекты сделали бы число вызовов наблюдаемым.

Поэтому проекция должна быть дешёвой и без побочных эффектов. Дорогие результаты лучше вычислить заранее и сохранить.

## Цена pull-модели

Ranges используют pull-модель: внешний потребитель запрашивает следующий элемент, а вызов проходит через всю цепочку вложенных итераторов.

Глубокие цепочки могут увеличить:

- сложность результирующего типа;
- время компиляции;
- размер машинного кода;
- глубину вызовов и расход стека без оптимизаций;
- нагрузку на оптимизатор.

Фактическая стоимость зависит от компилятора, уровня оптимизации и конкретных адаптеров.

## Висячие ссылки

```cpp
auto evenValues() {
    std::vector<int> values{1, 2, 3, 4};

    return values | std::views::filter([](int value) {
        return value % 2 == 0;
    });
}
```

Возвращённый view ссылается на уничтоженный локальный вектор. Его обход приводит к неопределённому поведению.

Нужно вернуть владеющий контейнер либо построить view над объектом с достаточным временем жизни.

## Flux

Flux обобщает не указатель-итератор, а индекс — курсор. Операции получают и последовательность, и курсор:

| Ranges | Flux |
|---|---|
| `begin(range)` | `flux::first(sequence)` |
| `iterator == end` | `flux::is_last(sequence, cursor)` |
| `++iterator` | `flux::inc(sequence, cursor)` |
| `*iterator` | `flux::read_at(sequence, cursor)` |

Курсор сам по себе не предоставляет доступ к элементу. Это уменьшает риск использовать позицию после уничтожения последовательности и позволяет централизованно проверять операции.

```cpp
#include <flux.hpp>

constexpr auto result = flux::ints()
    .filter(flux::pred::even)
    .map([](int value) { return value * 2; })
    .take(3)
    .sum();

static_assert(result == 12);
```

Flux тоже поддерживает ленивые конвейеры, но имеет другой фундаментальный интерфейс. Это молодая сторонняя библиотека, поэтому её совместимость и зрелость нужно оценивать отдельно.

## Подводные камни

### 1. Не считай любое чтение view чистой операцией

Первый вызов `begin()` некоторых отображений способен заполнить внутренний кеш.

### 2. `const view` не даёт глубокой константности

Для неизменяемого доступа используй view над константными данными или `views::as_const`.

### 3. Ставь дешёвый `filter` раньше

Но только если условие можно перенести до преобразования без изменения смысла программы.

### 4. Не используй побочные эффекты в проекциях

Стандарт не обещает ровно один вызов проекции на элемент.

### 5. Проверяй время жизни каждого слоя

Внешний view может косвенно хранить ссылку через несколько вложенных адаптеров.

### 6. Не делай выводы о производительности без измерений

Оптимизатор часто устраняет обёртки, но сложная цепочка иногда требует материализации или упрощения.

## Саммари

- Некоторые view кешируют позиции, поэтому их состояние и мутации данных требуют внимания.
- Константность view не равна константности элементов.
- `transform | filter` может повторно вычислять преобразование.
- Проекции algorithms могут вызываться многократно.
- Pull-цепочки создают вложенные типы и итераторы.
- Главный риск невладеющих view — висячие ссылки.
- Flux использует связку «последовательность + курсор» вместо автономного итератора.
