# 5. Базовые адаптеры диапазонов

## Суть

Адаптеры создают ленивое отображение другого диапазона:

- `std::views::filter` оставляет элементы по условию;
- `std::views::transform` преобразует элементы;
- `std::views::take` ограничивает их количество.

Исходный контейнер не копируется, а элементы вычисляются только при обходе.

## `std::views::filter`

```cpp
#include <ranges>
#include <vector>

std::vector<int> values{0, 5, -4, 10, -7};

auto nonNegative = std::views::filter(values, [](int value) {
    return value >= 0;
});

// 0, 5, 10
```

Предикат возвращает `true` для элементов, которые должны остаться.

## `std::views::transform`

```cpp
auto squares = std::views::transform(values, [](int value) {
    return value * value;
});
```

`transform` может изменять не только значение, но и тип элемента:

```cpp
struct Number {
    int value;
};

auto numbers = std::views::transform(values, [](int value) {
    return Number{std::abs(value)};
});
```

## Композиция адаптеров

Функциональный синтаксис:

```cpp
auto result = std::views::transform(
    std::views::filter(values, [](int x) { return x >= 0; }),
    [](int x) { return x * x; }
);
```

Pipe-синтаксис обычно читается проще:

```cpp
auto result = values
    | std::views::filter([](int x) { return x >= 0; })
    | std::views::transform([](int x) { return x * x; });
```

Операции выполняются слева направо: сначала фильтрация, затем преобразование.

## `std::views::take`

`take(N)` оставляет не более первых `N` элементов:

```cpp
auto firstThreeEven = std::views::iota(0)
                    | std::views::filter([](int x) {
                          return x % 2 == 0;
                      })
                    | std::views::take(3);

// 0, 2, 4
```

Благодаря ленивости `take` позволяет безопасно ограничивать бесконечный диапазон.

## Pull-модель

Ranges используют pull-модель: потребитель запрашивает следующий элемент, после чего цепочка вычисляет только его.

```cpp
auto view = values | std::views::transform(expensiveOperation);

auto it = view.begin();
auto first = *it; // expensiveOperation вызывается только сейчас
```

Создание `view` не запускает обработку всего диапазона.

## Подводные камни

### 1. Порядок адаптеров важен

`filter | transform` и `transform | filter` обрабатывают разные значения и могут иметь разную стоимость.

### 2. Вычисления могут повторяться

View обычно не кеширует результат. Новый обход снова вызовет предикаты и преобразования.

### 3. Избегай побочных эффектов

Число и порядок вызовов функций внутри адаптеров не стоит использовать как часть логики программы.

### 4. View часто зависит от исходного диапазона

Контейнер должен существовать во время обхода. Изменение контейнера может инвалидировать итераторы view.

### 5. `transform` не изменяет контейнер

Он предоставляет вычисленное представление элементов. Для изменения исходных данных нужен отдельный алгоритм или присваивание через подходящий view.

### 6. Не храни состояние в `transform`

Генерация Фибоначчи через `static`-переменные в лямбде зависит от истории обходов и небезопасна при повторном или параллельном использовании.

## Саммари

- `filter` лениво отбирает элементы по предикату.
- `transform` лениво преобразует значение или тип элемента.
- `take` ограничивает количество элементов.
- Адаптеры комбинируются функционально или через оператор `|`.
- Ranges используют pull-модель: вычисления запускает потребитель.
- Цепочки не требуют промежуточных контейнеров.
