# 2. Диапазоны и отображения

## Суть

Диапазон (`range`) — объект, для которого доступны `std::ranges::begin` и `std::ranges::end`.

Начало возвращает итератор, а конец — ограничитель (`sentinel`). Их типы могут различаться, но они должны сравниваться между собой.

```cpp
#include <algorithm>
#include <ranges>
#include <vector>

std::vector<int> values{4, 1, 3, 2};

std::ranges::sort(values);
auto it = std::ranges::find(values, 3);
```

Ranges-алгоритмы принимают контейнер целиком и проверяют требования через концепты. Например, `sort` требует `random_access_range`, поэтому `std::list` ему не подходит.

## Что является диапазоном

```cpp
std::vector<int> vector{1, 2, 3};
std::string_view text = "hello";
int array[]{1, 2, 3};

static_assert(std::ranges::range<decltype(vector)>);
static_assert(std::ranges::range<decltype(text)>);
static_assert(std::ranges::range<decltype(array)>);
```

Обычный указатель не является диапазоном: по нему нельзя определить конец последовательности.

## Отображения

Отображение (`view`) — легковесный диапазон. Оно обычно не копирует элементы, а предоставляет доступ к исходным данным или вычисляет значения при обходе.

Копирование и перемещение view должны выполняться за `O(1)`.

```cpp
std::vector<int> values{1, 2, 3};
auto view = std::views::all(values);

for (int x : view) {
    // 1, 2, 3
}
```

`std::views::all` выбирает подходящую обёртку:

- для lvalue обычно создаёт невладеющий `ref_view`;
- временный диапазон может переместить во владеющий `owning_view`.

```cpp
auto safe = std::views::all(std::vector{1, 2, 3});
```

`std::string_view` и `std::span` тоже удовлетворяют концепту `view`.

## Поддиапазоны

`std::ranges::subrange` хранит начало и ограничитель, представляя часть последовательности без копирования элементов.

```cpp
std::vector<int> values{10, 20, 30, 40};

auto middle = std::ranges::subrange(
    values.begin() + 1,
    values.end() - 1
);

// 20, 30
```

Типы итератора и ограничителя могут различаться. Это позволяет описывать потоки, условный конец и бесконечные последовательности.

## Common range

`common_range` — диапазон, у которого итератор и ограничитель имеют один тип. Все обычные контейнеры относятся к нему.

Если старому STL-алгоритму нужны два одинаковых итератора, необычный диапазон можно адаптировать:

```cpp
auto common = source | std::views::common;
auto sum = std::accumulate(common.begin(), common.end(), 0);
```

## Подводные камни

### 1. View может не владеть данными

Если исходный контейнер разрушен, обращение через невладеющий view недопустимо.

### 2. Изменение контейнера инвалидирует итераторы

Реаллокация `std::vector` может сделать созданные на его основе view и `subrange` невалидными.

### 3. `unreachable_sentinel` требует гарантии остановки

```cpp
auto it = std::ranges::find(
    values.begin(),
    std::unreachable_sentinel,
    30
);
```

Если значение не встретится, итератор уйдёт за допустимые границы — возникнет неопределённое поведение.

### 4. Не каждый диапазон можно сортировать

Наличие `begin` и `end` делает объект диапазоном, но конкретный алгоритм может требовать более сильный концепт.

### 5. `subrange` не копирует элементы

Он хранит границы исходной последовательности, поэтому зависит от её времени жизни.

## Саммари

- `range` предоставляет начало и конец последовательности.
- Конец может быть отдельным типом `sentinel`.
- `view` — дешёвое отображение данных или вычисляемой последовательности.
- `views::all` безопасно выбирает ссылочное или владеющее отображение.
- `subrange` описывает часть диапазона без копирования.
- `views::common` адаптирует диапазон для старых STL-алгоритмов.
