# 11. Отношения порядка

## Суть

| Отношение | Что означает |
| --- | --- |
| **sequenced-before** («упорядочено до») | Порядок вычислений внутри одного потока, заданный правилами языка |
| **synchronizes-with** («синхронизируется с») | Связь через механизм синхронизации, например release-запись и acquire-чтение, получившее её значение |
| **happens-before** («происходит до») | Порядок, объединяющий внутрипоточные шаги и связи синхронизации, в том числе транзитивно |

Для рассматриваемых примеров без `memory_order_consume`: если A sequenced-before B или A synchronizes-with B, то A happens-before B. Если A happens-before B и B happens-before C, то A happens-before C.

Это отношения абстрактной машины C++, а не показания часов или запрет любой перестановки машинных инструкций.

## Примеры

### Публикация данных: строим цепочку

```cpp
#include <atomic>
#include <string>

std::string data;
int bytes_count = 0;
std::atomic<bool> ready{false};

void Producer() {
    data = "hello";       // W1
    bytes_count = 5;       // W2
    ready.store(true);    // W3: seq_cst по умолчанию
}

void Consumer() {
    while (!ready.load()) {} // R1: интересует чтение, увидевшее true
    int size = bytes_count;  // R2: 5
    auto copy = data;        // R3: "hello"
}
```

Условия: один производитель, данные живут достаточно долго, после публикации больше не меняются.

- W1 sequenced-before W2 sequenced-before W3: отдельные последовательные выражения одного потока, даже для разных обычных переменных.
- W3 synchronizes-with успешным R1: запись имеет release-семантику, чтение — acquire-семантику и получает опубликованное `true`.
- R1 sequenced-before R2 sequenced-before R3.
- Значит, W2 happens-before R2, а W1 happens-before R3: чтения обычных данных безопасны.

Связи W1 → R1 и W3 → R3 тоже являются happens-before по цепочке; называть их непосредственно synchronizes-with неверно.

### Слишком ранний флаг готовности

```cpp
std::atomic<bool> ready{false};
std::atomic<int> value{0};

// Поток 1:
ready.store(true);
value.store(42);

// Поток 2:
while (!ready.load()) {}
int result = value.load(); // может быть 0: запись 42 ещё не выполнена
```

Гонки данных нет, но протокол неверен. Чтобы публиковать значение через флаг, запись `value` должна предшествовать записи `ready`. Если здесь заменить `value` на обычный `int`, получится гонка данных.

### Синхронизация без атомарного флага

```cpp
#include <thread>

int main() {
    int result = 0;
    std::jthread worker([&] { result = 42; });
    worker.join();
    int copy = result; // 42
}
```

Завершение потока синхронизируется с успешным возвратом из `join()`. Поэтому запись результата happens-before его чтения. Аналогично освобождение мьютекса синхронизируется с последующим захватом того же мьютекса.

## Подводные камни

- Sequenced-before определяется семантикой языка, а не только расположением текста «выше». Например, порядок вычисления аргументов функции не следует из порядка их записи.
- Отношение sequenced-before не требует общей переменной или атомика: последовательные записи в разные обычные переменные тоже упорядочены внутри потока.
- Не всякое чтение атомика синхронизируется с записью. Нужны подходящие порядки памяти и чтение соответствующей записи (либо её release sequence). У `relaxed` одной атомарности недостаточно.
- Synchronizes-with не обещает «самую свежую запись при следующем чтении» и не ограничено атомиками: оно возникает и у стандартных средств синхронизации.
- **Data race** возникает при потенциально конкурентных конфликтующих действиях, хотя бы одно из которых неатомарно, если ни одно не happens-before другого. Помимо записи, конфликт может затрагивать начало или конец времени жизни объекта.
- «Поток фактически успел раньше» без установленного отношения порядка не устраняет гонку данных. Сон, логирование и удачное расписание не заменяют синхронизацию.
- Два писателя обычных данных не становятся безопасными от того, что оба потом поднимают один атомарный флаг: их записи между собой не упорядочены.
- `happens-before` включает и прямые связи, и транзитивные цепочки. Оно не означает, что любые две операции программы упорядочены.
- `seq_cst` дополнительно задаёт общий порядок соответствующих атомарных операций; он не равен частичному порядку happens-before и не превращает обычные переменные в атомики.

## Саммари

Для передачи данных построй цепочку: запись данных → публикация → чтение публикации → чтение данных. Sequenced-before связывает шаги внутри потока, synchronizes-with соединяет синхронизирующие операции, а happens-before позволяет доказать безопасность всей цепочки.
