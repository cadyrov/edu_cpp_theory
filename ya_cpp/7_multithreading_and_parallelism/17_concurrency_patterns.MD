# 17. Паттерны проектирования

## Суть

- Потокобезопасность отдельных методов не гарантирует безопасность их комбинации. Ссылка из `Front()` может стать висячей сразу после освобождения мьютекса.
- **Транзакционный интерфейс** объединяет несколько действий под одной блокировкой. Он обеспечивает изоляцию от других защищённых обращений, но не автоматический откат при исключении.
- **MPMC** — несколько производителей и потребителей; **SPSC** — ровно один производитель и один потребитель. Более узкий контракт позволяет упростить синхронизацию.
- SPSC-очередь можно построить на кольцевом буфере: каждый индекс изменяет только один поток, а передачу владения слотами обеспечивают release/acquire.
- **False sharing** — лишняя конкуренция за кеш-линию, содержащую разные изменяемые данные. Это проблема производительности, а не data race.

## Примеры

### Работа с кешем под одной блокировкой

```cpp
#include <mutex>
#include <unordered_map>
#include <utility>

template <typename Key, typename Value>
class ThreadSafeCache {
    std::unordered_map<Key, Value> cache_;
    mutable std::mutex mutex_;

public:
    void Put(Key key, Value value) {
        std::lock_guard lock(mutex_);
        cache_.insert_or_assign(std::move(key), std::move(value));
    }

    template <typename Function>
    auto Apply(Function&& f) const {
        std::lock_guard lock(mutex_);
        return std::forward<Function>(f)(cache_);
    }
};

ThreadSafeCache<int, int> cache;
cache.Put(1, 10);
cache.Put(2, 20);
// Несколько чтений одного согласованного состояния:
auto values = cache.Apply([](const auto& map) {
    return std::pair{map.at(1), map.at(2)}; // копии; при отсутствии ключа — исключение
});
```

`mutable` позволяет захватить мьютекс в `const`-методе. Сам кеш передаётся как `const`; для изменения нескольких значений можно добавить неконстантный `Apply`, если это допустимо для интерфейса.

### Кольцевая SPSC-очередь

Учебный вариант: `N >= 2`, полезная ёмкость **N − 1**. `T` должен поддерживать конструирование по умолчанию, перемещающее присваивание и конструирование; для простоты считаем перемещения не бросающими исключений.

```cpp
#include <array>
#include <atomic>
#include <cstddef>
#include <optional>
#include <utility>

template <typename T, std::size_t N>
class SpscQueue {
    static_assert(N >= 2);
    std::array<T, N> buffer_{};
    std::atomic<std::size_t> write_{0}; // изменяет только производитель
    std::atomic<std::size_t> read_{0};  // изменяет только потребитель

public:
    bool Push(T value) {
        const auto write = write_.load(std::memory_order_relaxed);
        const auto next = (write + 1) % N;
        if (next == read_.load(std::memory_order_acquire)) return false;
        buffer_[write] = std::move(value);
        write_.store(next, std::memory_order_release);
        return true;
    }

    std::optional<T> Pop() {
        const auto read = read_.load(std::memory_order_relaxed);
        if (read == write_.load(std::memory_order_acquire)) return {};
        std::optional<T> result{std::move(buffer_[read])};
        read_.store((read + 1) % N, std::memory_order_release);
        return result;
    }
};
```

Производитель публикует готовый элемент через `write_`. Потребитель после перемещения публикует освобождение слота через `read_`. Обе связи нужны: первая защищает чтение элемента, вторая — его последующую перезапись.

Свой индекс читается с `relaxed`, чужой — с `acquire`. Равенство индексов означает пустоту; совпадение следующей позиции записи с позицией чтения — заполнение. Один слот оставлен свободным для различения этих состояний.

### Разделение индексов по кеш-линиям

Вместо соседних полей индексов можно использовать:

```cpp
// <new>, C++17; требуется поддержка константы стандартной библиотекой
alignas(std::hardware_destructive_interference_size)
    std::atomic<std::size_t> write_{0};
alignas(std::hardware_destructive_interference_size)
    std::atomic<std::size_t> read_{0};
```

Это разносит индексы согласно расстоянию, рекомендованному реализацией. Константа не является runtime-измерением кеш-линии; выигрыш проверяют измерением. Обмен самими индексами и конкуренция за соседние слоты буфера при этом не исчезают.

## Подводные камни

- Из `Apply` нельзя выпускать указатели, итераторы и ссылки на защищённые данные, в том числе сохранять их через захваты. Возврат через `auto` не защищает от таких обходных путей.
- Колбэк под мьютексом не должен повторно захватывать тот же мьютекс или создавать цикл с другими блокировками. Долгие вычисления и ввод-вывод увеличивают время ожидания.
- Исключение из изменяющего колбэка освобождает мьютекс, но не отменяет уже выполненные изменения. Для гарантии «всё или ничего» нужен отдельный механизм отката или подготовки и фиксации результата.
- У SPSC строго один вызывающий `Push` и один вызывающий `Pop`. Добавление второго производителя или потребителя нарушает алгоритм; атомарные индексы этого не исправляют.
- Единственный писатель не устраняет конфликт с читателем. Индексы всё равно атомарны, а доступ к обычным слотам упорядочивается release/acquire.
- `Push` и `Pop` не ждут места или данных. Неуспех не обещает, что очередь останется полной или пустой: другой поток может уже изменить её состояние.
- `Push(T value)` принимает владение параметром ещё до проверки места. После отказа нельзя повторно использовать исходный move-only объект, рассчитывая, что он сохранился; для такого контракта нужен другой интерфейс.
- Отсутствие CAS-циклов не доказывает wait-free всей операции: нужно учитывать реализацию атомиков и код `T`. Отсутствие явного мьютекса тоже не гарантирует lock-free.
- Очередь должна жить до завершения обоих потоков. Закрытие и остановка в учебной SPSC-реализации не предусмотрены — это отдельная часть протокола.
- False sharing возможен без единой гонки данных. Размер кеш-линии не обязан быть 64 байта, а выравнивание увеличивает расход памяти.

## Саммари

Проектируй интерфейс вокруг целой операции и времени жизни данных. Сначала уточни число производителей и потребителей; SPSC позволяет передавать слоты через два индекса. После доказательства корректности измеряй производительность и влияние false sharing.
