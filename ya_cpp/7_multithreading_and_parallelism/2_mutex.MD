# 2. Мьютексы и защита общих данных

## Суть

- `std::mutex` даёт одному потоку исключительный доступ к защищённым данным. Все конфликтующие обращения должны использовать **один и тот же мьютекс**.
- `lock()` ждёт и захватывает мьютекс; `try_lock()` пробует без ожидания и сообщает об успехе; `unlock()` освобождает его.
- `std::lock_guard` захватывает мьютекс в конструкторе и освобождает в деструкторе, в том числе при выходе по исключению. Используй RAII вместо ручной пары `lock()` / `unlock()`.
- **Data race** — несинхронизированные конфликтующие обращения к памяти, означающие UB. **Race condition** — зависимость результата от порядка событий; может оставаться даже при защите каждого отдельного обращения.
- Защищай всю логически неделимую операцию: «проверить и изменить», а не только отдельные чтения и записи.

## Примеры

### Устранение гонки данных

```cpp
#include <mutex>
#include <thread>

int main() {
    int value = 0;
    int result = 0;
    std::mutex mutex;
    {
        std::jthread writer([&] {
            std::lock_guard lock(mutex);
            value = 1;
        });
        std::jthread reader([&] {
            std::lock_guard lock(mutex);
            result = value;
        });
    } // оба потока завершены
    // result == 0 или 1: UB нет, порядок захвата не задан
}
```

Освобождение мьютекса синхронизируется с последующим захватом: изменения защищённых данных становятся видны следующему владельцу.

### Проверка и списание под одной блокировкой

Даже потокобезопасные `Get()` и `ChangeBy()` не делают выражение `if (Get() >= amount) ChangeBy(-amount)` безопасной операцией списания: между вызовами баланс может измениться.

```cpp
#include <mutex>

class Balance {
    std::mutex mutex_;
    int balance_;

public:
    explicit Balance(int initial) : balance_(initial) {}

    bool Withdraw(int amount) {
        std::lock_guard lock(mutex_);
        if (amount <= 0 || balance_ < amount) {
            return false;
        }
        balance_ -= amount;
        return true;
    }
};
```

### Рекурсивный захват

```cpp
std::recursive_mutex mutex;
{
    std::lock_guard outer(mutex);
    {
        std::lock_guard inner(mutex); // тот же поток захватил повторно
    } // освободили один уровень
} // теперь мьютекс доступен другим потокам
```

Для обычного `std::mutex` повторный захват владельцем — UB. В новом коде обычно лучше убрать вложенный захват: под блокировкой обращаться к данным напрямую или через приватный метод без собственной блокировки.

### Несколько читателей: `shared_mutex`

Для независимых чтений можно использовать общий захват, а для изменения — исключительный:

```cpp
// <shared_mutex>, <mutex>; поля и методы одного класса
mutable std::shared_mutex mutex_;
int value_ = 0;

int Get() const {
    std::shared_lock lock(mutex_);
    return value_;
}
void Set(int value) {
    std::unique_lock lock(mutex_);
    value_ = value;
}
```

Это не гарантирует ускорения или справедливости к писателю. Общий захват не допускает запись; для перехода к записи обычно нужно освободить его, захватить исключительный и **заново проверить условие**.

## Подводные камни

- Мьютекс не защищает данные автоматически: обращение в обход блокировки нарушает протокол защиты.
- Guard должен иметь имя: `std::lock_guard lock(mutex);`. Безымянный `std::lock_guard{mutex};` уничтожается уже в конце этой строки.
- Не вызывай `unlock()` без владения; после неудачного `try_lock()` владения нет. Сам `try_lock()` может вернуть `false`, даже если мьютекс свободен.
- Мьютекс нельзя копировать или перемещать. Он должен жить, пока потоки его используют; уничтожать захваченный мьютекс нельзя.
- Исключение освобождает RAII-блокировку, но не откатывает уже выполненные изменения данных.
- Не держи блокировку во время скачивания, сна или другой долгой работы: подготовь результат снаружи, затем кратко заблокируй запись в общую структуру.
- `unordered_map::reserve()` не делает параллельные вставки безопасными. Альтернатива: отдельные элементы заранее созданного вектора, затем сборка карты после завершения потоков.
- `recursive_mutex` разрешает повторный захват, но не исправляет ошибки логики и не устраняет все возможные взаимные блокировки.

## Саммари

Один мьютекс и именованный `lock_guard` защищают общие данные. Объединяй проверку и изменение под одной блокировкой, держи её недолго; где возможно, разделяй данные между потоками.
