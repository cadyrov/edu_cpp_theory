# 1. Потоки C++

## Суть

- С C++11 стандарт описывает потоки исполнения, модель памяти, синхронизацию и атомарные операции. Оптимизации компилятора должны учитывать эти правила.
- Потоки выполняют свои функции и могут обращаться к общей памяти. Порядок их выполнения заранее не известен.
- `std::thread` (C++11) запускает поток; владеющий объект можно перемещать, но нельзя копировать. Возвращаемое значение функции потока игнорируется.
- `join()` ждёт завершения потока; `detach()` отделяет его от объекта, но не останавливает.
- `std::jthread` (C++20) при уничтожении связанного с ним потока запрашивает остановку и вызывает `join()`. Для обычного владения потоком удобнее начинать с него.
- **Гонка данных**: конфликтующие обращения к одной области памяти из разных потоков, хотя бы одно неатомарное, без отношения *happens-before*. Например, запись и чтение обычного `int` без синхронизации. Это UB.

## Примеры

### Запуск и ожидание

```cpp
#include <iostream>
#include <thread>

int main() {
    std::thread t([] { std::cout << "Hello\n"; });
    t.join(); // ждём явно

    std::jthread jt([] { std::cout << "Hello again\n"; });
} // jt автоматически ждёт завершения
```

### Аргументы и результат через ссылку

Вызываемый объект и аргументы сохраняются по значению: копируются или перемещаются. Для ссылки используй `std::ref` / `std::cref` либо захват лямбды по ссылке.

```cpp
#include <functional>
#include <thread>

void Calculate(int input, int& output) {
    output = input * 2;
}

int main() {
    int result = 0;
    {
        std::jthread t(Calculate, 21, std::ref(result));
    } // join: запись завершена и видна текущему потоку
    // теперь result == 42, читать безопасно
}
```

### Гонка данных

```cpp
int value = 0;
int result = 0;
{
    std::jthread writer([&] { value = 1; });
    std::jthread reader([&] { result = value; }); // UB
}
```

Ожидание обоих потоков в конце не упорядочивает их обращения к `value`. Нужны синхронизация, атомарные операции или разделение данных. Совместное чтение без записи безопасно.

### Полезные функции

```cpp
using namespace std::chrono_literals;
auto count = std::thread::hardware_concurrency(); // подсказка; может быть 0
auto id = std::this_thread::get_id();             // ID текущего потока
std::this_thread::sleep_for(10ms);                // <chrono>, <thread>
```

`t.get_id()` возвращает ID связанного потока; `sleep_until()` ждёт до заданного момента времени.

### Передача исключения вызывающему потоку

`join()` не переносит исключения автоматически. Работник может сохранить `exception_ptr`, а вызывающий код — повторно выбросить его после ожидания:

```cpp
// <exception>, <thread>; фрагмент внутри функции, DoWork() — полезная работа
std::exception_ptr error;
std::jthread worker([&] {
    try { DoWork(); }
    catch (...) { error = std::current_exception(); }
});
worker.join();
if (error) std::rethrow_exception(error);
```

Здесь один писатель, чтение только после `join()`: дополнительный мьютекс для `error` не нужен. Создание самого потока тоже может бросить исключение, например при нехватке ресурсов.

## Подводные камни

- Уничтожение `std::thread`, для которого `joinable() == true`, вызывает `std::terminate`, даже если работа уже закончилась. Исключение до `join()` тоже опасно.
- `joinable()` означает связь с потоком, а не то, что он ещё выполняется. После `join()` или `detach()` повторный вызов недопустим; ожидание самого себя тоже ошибочно.
- Исключение, покинувшее функцию потока, вызывает `std::terminate`; автоматический `join()` от этого не защищает.
- `std::jthread` не прерывает работу принудительно: запрос остановки должен обрабатываться кодом потока. Деструктор может долго ждать.
- Указатели, ссылки, `span` и `string_view` не продлевают жизнь данных. Объявляй данные до `jthread`, чтобы поток уничтожился раньше них.
- После `detach()` автоматического ожидания нет. Завершение `main()` завершает программу и не ждёт отделённых потоков.
- `hardware_concurrency() == 0` означает, что число неизвестно, а не отсутствие поддержки потоков.
- `sleep_for()` и `volatile` не обеспечивают синхронизацию. При гонке данных нельзя обещать даже результат «0 или 1».
- Разные обычные элементы контейнера можно изменять независимо, если сам контейнер не меняет структуру. У `vector<bool>` это не гарантируется; общая линия кеша сама по себе не означает гонку данных.

## Саммари

Запускай работу через `std::jthread`, обеспечивай жизнь переданных данных и читай результаты после `join()`. Общая память требует синхронизации: гонка данных — UB, а не просто непредсказуемый порядок.
