# 6. Параллельные алгоритмы

## Суть

Многие алгоритмы из `<algorithm>` и `<numeric>` принимают первым аргументом политику из `<execution>`. Она разрешает способ исполнения; распределением работы занимается стандартная библиотека.

| Политика | Исполнение |
| --- | --- |
| `seq` (C++17) | Последовательно в вызывающем потоке |
| `par` (C++17) | Разрешено несколько потоков; вызовы внутри одного потока не перекрываются |
| `par_unseq` (C++17) | Разрешены несколько потоков и неупорядоченные вызовы внутри потока, в том числе SIMD |
| `unseq` (C++20) | Неупорядоченные вызовы в вызывающем потоке, в том числе SIMD |

Параллелизм и SIMD не гарантированы. SIMD означает обработку нескольких значений одной инструкцией, а не обещание выполнить всю работу за один такт. Обычный последовательный код тоже может автоматически векторизоваться.

## Примеры

### `copy_if`: заранее создать выходные элементы

```cpp
#include <algorithm>
#include <execution>
#include <numeric>
#include <vector>

std::vector<int> source(1'000'000);
std::iota(source.begin(), source.end(), 1);
std::vector<int> result(source.size());

auto end = std::copy_if(std::execution::par_unseq,
                       source.begin(), source.end(), result.begin(),
                       [](int x) { return x % 2 == 0; });
result.erase(end, result.end()); // оставить только скопированные элементы
```

`copy_if` сохраняет взаимный порядок выбранных элементов, хотя порядок вызовов предиката не задан.

### `transform`: независимая обработка элементов

```cpp
std::vector<int> first(1'000'000, 5);
std::vector<int> second(first.size(), 3);
std::vector<int> result(first.size());

std::transform(std::execution::par,
               first.begin(), first.end(), second.begin(), result.begin(),
               [](int a, int b) { return a + b; });
```

Каждая операция записывает в свой элемент. Второй входной диапазон и выходной диапазон должны быть достаточно велики.

### `reduce`: свёртка без фиксированного порядка

```cpp
std::vector<long long> data(1'000'000);
std::iota(data.begin(), data.end(), 1LL);

auto sum = std::reduce(std::execution::par,
                       data.begin(), data.end(), 0LL);
// 500'000'500'000 — не помещается в обычный 32-битный int
```

`accumulate` сворачивает слева направо; `reduce` может менять порядок и группировку даже с `seq`. Для независимого от порядка результата операция должна быть ассоциативной и коммутативной в используемом типе. Вычитание, деление и склейка строк для этого не подходят; сумма `double` может различаться из-за округления.

### Измерение производительности

- Сравнивай политики на одинаковых данных и нескольких размерах в сборке с оптимизациями. Генерацию данных и выделение выходного буфера вынеси из измеряемого участка.
- Для времени выполнения используй `std::chrono::steady_clock`; сделай несколько повторов и используй результат, чтобы вычисление не исчезло при оптимизации.
- В Google Benchmark используй `UseRealTime()` для сравнения прошедшего времени параллельных алгоритмов; защищай измеряемые вычисления от удаления через `DoNotOptimize` и при необходимости `ClobberMemory`.
- Маленькие задачи часто проигрывают из-за накладных расходов. Простые операции над большими массивами могут упираться в пропускную способность памяти; тяжёлые независимые вычисления чаще выигрывают.
- Универсального порога размера и гарантированного ускорения нет: результат зависит от алгоритма, библиотеки, процессора и текущей нагрузки.

### `transform_reduce`: вычислить и сразу свернуть

```cpp
// <execution>, <numeric>, <functional>, <vector>
std::vector<int> values{1, 2, 3, 4};
auto squares = std::transform_reduce(
    std::execution::par, values.begin(), values.end(), 0LL,
    std::plus<long long>{}, [](int x) { return 1LL * x * x; });
// squares == 30; промежуточный вектор не нужен
```

Как и у `reduce`, группировка не фиксирована. Умножение расширяется до `long long` **до** вычисления квадрата; итоговая сумма тоже должна помещаться в выбранный тип.

## Подводные камни

- `reserve()` меняет ёмкость, но не размер: писать через `begin()` пустого вектора нельзя. Нужен `resize()` или конструктор с размером.
- Перегрузки рассматриваемых алгоритмов с политикой требуют forward-итераторы; `std::back_inserter` не подходит. Параллельный `push_back()` в общий вектор тоже небезопасен.
- Общий `sum += x` внутри `for_each(par, ...)` создаёт гонку данных. Для суммы выбирай `reduce`, а не общий счётчик с конкурирующими записями.
- **С `par` мьютекс допустим**: короткая независимая критическая секция сама по себе не означает дедлок. Но нельзя ждать, пока другая итерация начнёт или закончит работу: алгоритм может выполняться последовательно.
- С `unseq` и `par_unseq` нельзя использовать мьютексы и другие операции, небезопасные при векторизации. Потокобезопасности колбэка недостаточно; предпочитай независимые вычисления без побочных эффектов.
- Исключение, покинувшее пользовательскую функцию в алгоритме со стандартной политикой, вызывает `std::terminate`, включая `seq`. Поэтому `seq` не полностью эквивалентна вызову без политики.
- Проверяй переполнение промежуточных вычислений: знаковое переполнение — UB. В примере суммы и элементы, и начальное значение имеют тип `long long`.
- Запрос `par` не доказывает, что библиотека действительно задействовала несколько потоков. Не переносись на другую систему с ожиданием тех же результатов замеров.

## Саммари

Выбирай политику для независимых операций, заранее создавай выходные элементы и учитывай ограничения колбэков. Используй `reduce` только с подходящей операцией, а выигрыш от параллелизма подтверждай измерениями.
