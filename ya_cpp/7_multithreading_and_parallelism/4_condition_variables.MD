# 4. Условные переменные

## Суть

- Постоянная проверка очереди тратит CPU; проверка с `sleep_for()` добавляет задержку. `std::condition_variable` позволяет спать до уведомления и повторно проверять условие.
- Условная переменная работает вместе с **состоянием и мьютексом**. Состояние хранит факт готовности; уведомление само по себе не запоминается.
- `wait(lock, predicate)` проверяет условие под мьютексом. Если оно ложно, атомарно освобождает мьютекс и начинает ожидание; перед повторной проверкой снова захватывает мьютекс.
- `notify_one()` будит одного ожидающего, `notify_all()` — всех. Пробуждение не гарантирует, что условие выполнено или поток сразу получит CPU.
- Для ожидания нужен `std::unique_lock<std::mutex>`: в отличие от `lock_guard`, он позволяет временно отпускать и снова захватывать мьютекс.

## Примеры

### Производитель и потребитель

```cpp
#include <condition_variable>
#include <mutex>
#include <queue>
#include <thread>

void ProcessTask(int id) {
    // полезная работа
}

int main() {
    std::queue<int> tasks;
    std::mutex mutex;
    std::condition_variable cv;
    bool done = false;

    std::jthread producer([&] {
        for (int id = 0; id < 10; ++id) {
            {
                std::lock_guard lock(mutex);
                tasks.push(id);
            }
            cv.notify_one();
        }
        {
            std::lock_guard lock(mutex);
            done = true;
        }
        cv.notify_all();
    });

    std::jthread consumer([&] {
        while (true) {
            std::unique_lock lock(mutex);
            cv.wait(lock, [&] { return done || !tasks.empty(); });
            if (tasks.empty()) {
                return; // done == true, все задачи извлечены
            }
            int id = tasks.front();
            tasks.pop();
            lock.unlock();
            ProcessTask(id); // долгая работа вне блокировки
        }
    });
} // потоки завершаются до уничтожения общих данных
```

Флаг `done` завершает ожидание даже при пустой очереди. Если в очереди ещё есть задачи, потребитель сначала обработает их.

### Ожидание с предикатом

```cpp
cv.wait(lock, [&] { return ready; });

// Эквивалентно:
while (!ready) {
    cv.wait(lock);
}
```

Цикл обязателен: возможны ложные пробуждения, а при нескольких потребителях задачу может забрать другой поток.

### Возможности `unique_lock`

- `unlock()` освобождает мьютекс, `lock()` захватывает снова; деструктор освобождает его только при владении.
- `owns_lock()` и преобразование в `bool` сообщают о владении. Объект можно перемещать, но нельзя копировать.
- `std::defer_lock` откладывает захват; `std::adopt_lock` принимает уже захваченный текущим потоком мьютекс.
- `try_lock()` пробует захват без ожидания; `try_lock_for()` / `try_lock_until()` требуют мьютекс с поддержкой таймаутов, например `std::timed_mutex`.
- `release()` отвязывает обёртку и возвращает указатель на мьютекс, **не освобождая его**.

### Ожидание с общим сроком

```cpp
// <chrono>; mutex, cv и ready — общее состояние
std::unique_lock lock(mutex);
const auto deadline = std::chrono::steady_clock::now()
                    + std::chrono::milliseconds(100);
bool ready_in_time = cv.wait_until(lock, deadline, [&] { return ready; });
// false: при окончательной проверке предикат остался ложным
```

`wait_for(lock, duration, pred)` также ограничивает ожидание. Если вручную повторять ожидания в цикле, используй один deadline: новый полный интервал после каждого пробуждения может бесконечно продлевать общий срок. Возврат может задержаться из-за планирования и повторного захвата мьютекса. [Контракт ожидания в C++20](https://timsong-cpp.github.io/cppwp/n4861/thread.condition.condvar).

Если на одной условной переменной ждут разные предикаты, `notify_one()` может разбудить неподходящего участника. Раздели условия на разные переменные или используй `notify_all()`.

## Подводные камни

- В `wait()` передавай `unique_lock`, уже владеющий мьютексом. Все одновременно ожидающие на одной `condition_variable` должны использовать один и тот же мьютекс.
- Проверяй и изменяй состояние предиката под этим мьютексом. Даже атомарный флаг сам по себе не предотвращает потерю уведомления между проверкой и началом ожидания.
- `notify_*()` не заменяет изменение состояния. Уведомление, отправленное до появления ожидающих, не сохраняется; сохранённое состояние позволяет не засыпать зря.
- Обычно уведомляй после освобождения мьютекса, чтобы разбуженный поток мог его захватить. Уведомлять под блокировкой тоже корректно; время жизни условной переменной должно покрывать все обращения к ней.
- Предусмотри завершение: изменить флаг под мьютексом и разбудить ожидающих. Обычный `condition_variable::wait()` не прерывается автоматически запросом остановки `jthread`.
- `std::condition_variable_any` — **не шаблон класса**. Его методы ожидания работают с разными типами блокировок, поддерживающими `lock()` / `unlock()`; с C++20 есть перегрузки со `stop_token`.

## Саммари

Храни условие в общих данных, защищай их одним мьютексом, жди через `unique_lock` и `wait` с предикатом. После изменения состояния уведомляй ожидающих, а полезную работу выполняй вне блокировки.
