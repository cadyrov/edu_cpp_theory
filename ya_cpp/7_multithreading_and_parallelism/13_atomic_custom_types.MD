# 13. Шаблон атомарного типа

## Суть

- Основной шаблон `std::atomic<T>` подходит для тривиально копируемого типа, который также допускает копирующее и перемещающее конструирование и присваивание; сам `T` должен быть без `const` / `volatile`.
- Атомарная структура позволяет получать согласованный снимок всех её полей одной операцией. Набор методов базовый: чтение, запись, обмен, CAS, проверка lock-free и с C++20 ожидание/уведомления.
- `std::atomic<T*>` атомарно меняет адрес, но не защищает содержимое объекта и не управляет его временем жизни.
- `std::atomic<std::shared_ptr<T>>` (C++20) — специальная поддержка нетривиального типа. Атомарное чтение получает владеющую копию указателя, сохраняющую объект живым.
- Ни атомарная структура, ни атомарный указатель, ни атомарный `shared_ptr` не имеют общей гарантии lock-free: проверяй `is_lock_free()`.

## Примеры

### Согласованные координаты

```cpp
#include <atomic>
#include <type_traits>

struct Position {
    double x;
    double y;
};

static_assert(std::is_trivially_copyable_v<Position>);
std::atomic<Position> pos{Position{0.0, 0.0}};

void Move() {
    pos.store(Position{10.0, 20.0}, std::memory_order_relaxed);
}

Position Snapshot() {
    return pos.load(std::memory_order_relaxed);
}
```

Читатель получает одну целую позицию, а не `x` от одного обновления и `y` от другого. `relaxed` достаточен, если координаты не публикуют другие данные. Два отдельных `atomic<double>` такого согласованного снимка не гарантируют.

### Атомарный адрес не продлевает жизнь объекта

```cpp
std::atomic<Position*> current{nullptr};

// Читатель:
Position* snapshot = current.load();

// Писатель в другом потоке:
Position* old = current.exchange(new Position{1.0, 2.0});
// delete old; // опасно: читатель ещё может использовать snapshot
```

Нужен отдельный протокол освобождения памяти. Сам атомарный указатель не требует динамического выделения: он может ссылаться и на объект с заранее обеспеченным временем жизни.

### Неизменяемые снимки через `atomic<shared_ptr>`

```cpp
#include <atomic>
#include <memory>
#include <string>

struct Settings {
    std::string endpoint;
    int timeout_ms;
};

std::atomic<std::shared_ptr<const Settings>> settings{
    std::make_shared<const Settings>(Settings{"localhost", 1000})
};

void UpdateSettings() {
    auto next = std::make_shared<const Settings>(Settings{"server", 2000});
    settings.store(next, std::memory_order_release);
}

int ReadTimeout() {
    auto snapshot = settings.load(std::memory_order_acquire);
    return snapshot->timeout_ms;
}
```

Писатель создаёт новый объект и публикует его. Читатель удерживает локальный `shared_ptr`: последующая замена не уничтожит его снимок. `load()` копирует указатель с владением, а не содержимое `Settings`.

## Подводные камни

- Требования основного шаблона не означают «только структуры из чисел»: проверяй свойства типа. Пользовательский обычный конструктор сам по себе не мешает тривиальному копированию.
- `std::string` и `std::vector` напрямую не подходят для основного шаблона. Атомарный `shared_ptr` решает публикацию снимка через отдельную специализацию.
- CAS обычного `atomic<T>` сравнивает представление значения, а не вызывает пользовательский `operator==`. Для floating-point и типов с несколькими представлениями одинакового значения это существенно.
- Один `load()` даёт снимок, но цепочка `load → изменить → store` не является атомарным обновлением. При нескольких писателях изменения могут теряться; нужен CAS-цикл или мьютекс.
- Разные обычные `shared_ptr`, разделяющие владение, могут независимо копироваться и сбрасываться в разных потоках. Конкурентная запись в один и тот же экземпляр требует синхронизации.
- Атомарность `shared_ptr` не делает атомарным `*ptr`. Изменять объект можно только при отдельной корректной синхронизации; для снимков проще публиковать неизменяемые объекты.
- `shared_ptr<const T>` ограничивает доступ через этот указатель, но не устраняет другие изменяемые алиасы или общие объекты, на которые ссылается `T`.
- Объект уничтожается после освобождения последнего владеющего указателя, а не после завершения всех читавших потоков. Сохраняй локальный снимок на всё время обращения к данным.
- `store()` заменяет указатель, а не редактирует прежний объект. Есть также `exchange()` и CAS; замена может повлечь работу деструктора старого объекта и не обязана быть дешёвой.
- Захват общего атомика по ссылке в отсоединённом потоке опасен, если сам атомик может быть уничтожен раньше потока. Владение опубликованными объектами эту проблему не решает.

## Саммари

Для небольшого подходящего значения используй `atomic<T>` и получай цельный снимок. Для сложных данных публикуй неизменяемый объект через `atomic<shared_ptr<const T>>`: атомарная замена обеспечивает передачу, а локальная владеющая копия — время жизни.
