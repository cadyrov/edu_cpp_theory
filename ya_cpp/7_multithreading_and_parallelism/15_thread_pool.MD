# 15. Пул потоков

## Суть

- **Пул потоков** — фиксированный набор работников и общая очередь задач. Потоки создаются один раз и переиспользуются.
- Пул ограничивает количество одновременно выполняемых задач и снижает расходы на создание потоков. Ускорение каждой задачи не гарантировано.
- Работник извлекает задачу под мьютексом, выполняет без блокировки очереди и возвращается за следующей. При пустой очереди ждёт через условную переменную.
- `hardware_concurrency()` — подсказка, а не оптимальный размер пула. При результате `0` используй запасной вариант, например один поток.
- Заранее выбери завершение: **доработать очередь** или **завершить только уже взятые задачи**. Ниже используется второй вариант, как в задании.

## Примеры

### Данные пула и работа потока

Фрагменты относятся к одному классу `ThreadPool`. Нужны заголовки `<condition_variable>`, `<functional>`, `<mutex>`, `<queue>`, `<thread>`, `<vector>`, `<utility>` и `<stdexcept>`.

```cpp
std::mutex mutex_;
std::condition_variable cv_;
std::queue<std::function<void()>> tasks_;
bool stopping_ = false; // все обращения под mutex_
std::vector<std::jthread> workers_; // объявлен последним

void Worker() {
    while (true) {
        std::function<void()> task;
        {
            std::unique_lock lock(mutex_);
            cv_.wait(lock, [&] { return stopping_ || !tasks_.empty(); });
            if (stopping_) {
                return; // оставшуюся очередь не выполняем
            }
            task = std::move(tasks_.front());
            tasks_.pop();
        }
        task(); // контракт примера: задача не выпускает исключения
    }
}
```

Конструктор запускает положительное число работников через `workers_.emplace_back([this] { Worker(); });`. Общие данные должны быть готовы до первого запуска. Извлечённая до остановки задача выполняется, даже если её тело ещё не успело начаться.

### Постановка задачи

```cpp
void Push(std::function<void()> task) {
    if (!task) {
        throw std::invalid_argument("Empty task");
    }
    {
        std::lock_guard lock(mutex_);
        if (stopping_) {
            throw std::runtime_error("Pool is stopping");
        }
        tasks_.push(std::move(task));
    }
    cv_.notify_one();
}
```

### Остановка

```cpp
~ThreadPool() {
    {
        std::lock_guard lock(mutex_);
        stopping_ = true;
    }
    cv_.notify_all();
    for (auto& worker : workers_) {
        if (worker.joinable()) {
            worker.join();
        }
    }
}
```

`join()` выполняется без захваченного `mutex_`. Для доработки очереди условие выхода в `Worker` должно быть `stopping_ && tasks_.empty()` вместо просто `stopping_`.

### Владение изображением в отложенной задаче

```cpp
void Process(Image&& image) {
    pool_.Push([image = std::move(image)]() mutable {
        GrayScaleFilter filter;
        filter.Filter(image);
        SaveImage(image);
    });
}
```

Изображение принадлежит задаче и живёт после возврата из `Process`. Фильтр и сохранение предполагаются потокобезопасными; исключения обрабатываются согласно контракту пула.

### Исключение при запуске работников

Конструктор для показанных выше полей и методов:

```cpp
explicit ThreadPool(std::size_t count) {
    if (count == 0) count = 1;
    workers_.reserve(count);
    try {
        for (std::size_t i = 0; i < count; ++i) {
            workers_.emplace_back([this] { Worker(); });
        }
    } catch (...) {
        {
            std::lock_guard lock(mutex_);
            stopping_ = true;
        }
        cv_.notify_all();
        throw; // вектор jthread уничтожится первым и дождётся работников
    }
}
```

Здесь принципиально, что `workers_` объявлен последним: очередь, условная переменная и мьютекс ещё живы при ожидании. Обычный `std::thread` потребовал бы явного присоединения в обработчике.

Пустая очередь не означает завершения пула: работники могли уже забрать задачи. Для отдельного `WaitIdle()` нужны также счётчик выполняемых задач и условие `tasks_.empty() && running_ == 0` под одним мьютексом. При продолжающихся `Push()` это лишь ожидание момента покоя, а не запрет будущей работы.

## Подводные камни

- `yield()` не означает сон: цикл с ним может расходовать CPU. Для пустой очереди используй `wait` с предикатом.
- Флаг под мьютексом не обязан быть атомарным. Атомарный флаг сам по себе не будит условную переменную.
- Если создание потока в конструкторе бросит исключение, деструктор самого пула не выполнится. Нужно остановить, разбудить и дождаться уже созданных работников при обработке ошибки конструктора.
- Не допускай вызовов `Push` одновременно с уничтожением пула. Проверка `stopping_` не защищает время жизни объекта.
- Не уничтожай пул из его работника: ожидание собственного потока недопустимо. Очередь и средства синхронизации должны жить до завершения работников.
- Исключение, покинувшее задачу, приводит к `std::terminate`. Общему пулу нужен явный способ сообщать ошибки; молча терять их нельзя.
- `std::function<void()>` требует копируемый вызываемый объект. Лямбда, владеющая `unique_ptr`, напрямую не подойдёт.
- Захваты по ссылке и через `this` требуют достаточного времени жизни объектов. Постановка задачи не означает завершения работы.
- Если все работники ждут дочерние задачи того же пула, возможен дедлок. FIFO-очередь не гарантирует порядок завершения задач.
- Неограниченная очередь может исчерпать память при перегрузке: ограничение числа потоков не ограничивает накопленную работу.
- Отмена остатка очереди не гарантирует сохранения всех изображений. Для этого нужен режим доработки или отдельное ожидание всех принятых задач.

## Саммари

Пул переиспользует потоки и распределяет задачи через защищённую очередь. Жди без активного цикла, выполняй задачи вне блокировки и явно определяй владение данными, обработку ошибок и правила завершения.
