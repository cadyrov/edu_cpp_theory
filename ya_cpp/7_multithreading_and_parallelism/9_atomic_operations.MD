# 9. Операции над атомарными типами

## Суть

`std::atomic<int>` поддерживает знакомые `load`, `store`, `exchange`, CAS и ожидание, а также арифметические и побитовые read-modify-write (RMW) операции.

| Операция | Действие | Возвращает |
| --- | --- | --- |
| `fetch_add(n)` / `fetch_sub(n)` | Прибавить / вычесть `n` | Старое значение |
| `value++` / `value--` | Прибавить / вычесть 1 | Старое значение |
| `++value` / `--value` | Прибавить / вычесть 1 | Новое значение |
| `fetch_and(mask)` | Побитовое И | Старое значение |
| `fetch_or(mask)` | Побитовое ИЛИ | Старое значение |
| `fetch_xor(mask)` | Побитовое исключающее ИЛИ | Старое значение |

Эти операции над целочисленными атомиками **не доступны у `std::atomic<bool>`**. Обычное выражение из нескольких атомарных операций не превращается в одну RMW-операцию.

## Примеры

### Атомарный счётчик

```cpp
#include <atomic>
#include <thread>

int main() {
    std::atomic<int> count{0};
    {
        auto increment = [&] {
            for (int i = 0; i < 1'000; ++i) {
                count.fetch_add(1);
            }
        };
        std::jthread first(increment);
        std::jthread second(increment);
    }
    int total = count.load(); // 2000
}
```

`count = count + 1` — отдельные чтение и запись: гонки данных на атомике нет, но обновление другого потока можно потерять. `++count` и `count.fetch_add(1)` выполняют неделимое обновление.

### Побитовые флаги

```cpp
std::atomic<unsigned> flags{0};
unsigned old = flags.fetch_or(0b0101u); // old == 0, flags == 5
old = flags.fetch_or(0b1100u);          // old == 5, flags == 13
old = flags.fetch_and(0b0110u);         // old == 13, flags == 4
old = flags.fetch_xor(0b1111u);         // old == 4, flags == 11
```

Комментарии описывают выполнение без других писателей. При конкуренции возвращённое значение относится к конкретной RMW-операции, а следующее `load()` уже может увидеть чужое изменение.

### Свободные функции вместо методов

```cpp
std::atomic<int> value{42};
std::atomic_store(&value, 100);                 // value.store(100)
int old = std::atomic_fetch_add(&value, 5);     // old == 100, value == 105
old = std::atomic_exchange(&value, 50);         // old == 105, value == 50

int expected = 30;
bool success = std::atomic_compare_exchange_strong(&value, &expected, 40);
// success == false, expected == 50, value == 50
```

Первый аргумент — указатель на атомик; `expected` у свободного CAS тоже передаётся по указателю. Семантика соответствует методам; для CAS, чтения, записи и RMW есть варианты `_explicit` с порядком памяти:

```cpp
std::atomic_store_explicit(&value, 10, std::memory_order_seq_cst);
```

### Ожидание через свободные функции (C++20)

```cpp
std::atomic<int> state{0};

// Производитель:
std::atomic_store(&state, 42);
std::atomic_notify_one(&state);

// Потребитель в другом потоке:
std::atomic_wait(&state, 0); // ждёт значение, отличное от 0
int result = std::atomic_load(&state);
```

`result == 42` гарантировано здесь только при отсутствии других изменений. Ожидание не фиксирует значение навсегда и не означает ожидание именно числа 42.

### Арифметика атомарного указателя

```cpp
int data[4]{10, 20, 30, 40};
std::atomic<int*> cursor{data};
int* previous = cursor.fetch_add(2); // previous == data, cursor == data + 2
int value = *cursor.load();         // 30; других изменений здесь нет
```

Прибавляется число **элементов**, а не байтов. Атомарность адреса не делает безопасным разыменование за пределами массива и не защищает сами элементы.

## Подводные камни

- С C++20 конструктор по умолчанию `atomic<int>` инициализирует значение нулём; до C++20 полагаться на него нельзя. Явное `{0}` понятно в любой версии.
- Lock-free реализация `atomic<int>` не гарантирована: проверяй `is_lock_free()`, если это требование алгоритма.
- Арифметические RMW для знаковых целочисленных атомиков имеют определённое поведение переполнения. Это не распространяется на обычное `int`-выражение вроде `expected + 1` и не спасает логику переполненного счётчика.
- `fetch_add` / `fetch_sub` есть также у подходящих атомарных указателей и с C++20 у атомарных floating-point типов; наборы остальных операций отличаются.
- CAS при неудаче обновляет `expected`. В цикле пересчитывай желаемое значение или восстанавливай требуемое ожидаемое состояние в зависимости от задачи.
- Атомарные счётчики владения `shared_ptr` позволяют работать с разными экземплярами, делящими владение. Они не защищают сам объект и не разрешают несинхронизированно менять один экземпляр `shared_ptr` из разных потоков.
- Свободные функции имеют C-подобный интерфейс, но код со `std::atomic` не становится от этого исходным кодом на C. У `notify_*` нет порядка памяти и вариантов `_explicit`.
- Не помещай необходимые изменения в `assert(...)`: с `NDEBUG` выражение исчезнет. `assert(success = true)` к тому же присваивает значение вместо проверки.

## Саммари

Используй RMW для неделимого изменения счётчиков и битовых масок. Различай старое и новое возвращаемое значение, учитывай обновление `expected` в CAS. Методы и свободные функции дают одну семантику, но не делают составной алгоритм автоматически корректным.
