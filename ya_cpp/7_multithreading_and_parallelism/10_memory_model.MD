# 10. Модель памяти

## Суть

- Модель памяти C++ определяет допустимые значения чтений, гонки данных и отношения порядка между операциями потоков.
- Компилятор может преобразовывать код по правилу **as-if**, сохраняя требуемое стандартом наблюдаемое поведение. Он обязан учитывать многопоточную семантику корректной программы, а не считать весь код однопоточным.
- Процессор тоже может выполнять операции вне порядка, а буферы записи — задерживать видимость записей для других ядер. Порядок строк исходника не задаёт общий порядок наблюдений всех потоков.
- Синхронизация ограничивает допустимое поведение. Она не требует буквально исполнять каждую машинную инструкцию в порядке исходного текста.
- Мьютексы, атомики, запуск и завершение потоков участвуют в модели памяти. Она относится и к обычным данным, доступ к которым эти механизмы упорядочивают.

## Примеры

### Перестановки, сохраняющие смысл

```cpp
int a = 0, b = 10;

void Update() {
    a = b + 1;
    b = 0;
}
```

Компилятор может сначала сохранить старое `b` во временное значение, затем записать `b = 0` и только потом обновить `a`. Однопоточный результат тот же. Несинхронизированное чтение этих обычных переменных из другого потока создало бы data race, а не корректный способ наблюдать перестановки.

### Два атомика: `relaxed` и `seq_cst`

```cpp
#include <atomic>
#include <thread>

int main() {
    std::atomic<int> x{0}, y{0};
    int r1 = -1, r2 = -1;
    {
        std::jthread first([&] {
            x.store(1, std::memory_order_relaxed);
            r1 = y.load(std::memory_order_relaxed);
        });
        std::jthread second([&] {
            y.store(1, std::memory_order_relaxed);
            r2 = x.load(std::memory_order_relaxed);
        });
    }
    // r1 == 0 и r2 == 0 одновременно допустимо
}
```

Здесь нет гонки данных: `x` и `y` атомарны, а результаты читаются после завершения потоков. `relaxed` не задаёт общего порядка между операциями над разными атомиками. Один из аппаратных механизмов такого результата — store buffering.

Если убрать аргументы порядка памяти у **всех четырёх** операций, получится `seq_cst` по умолчанию. Тогда пара `(0, 0)` запрещена: единый порядок этих атомарных операций должен согласовываться с порядком внутри потоков. Возможны `(0, 1)`, `(1, 0)` и `(1, 1)`.

### Публикация обычных данных через атомарный флаг

```cpp
#include <atomic>
#include <string>

std::string data;
std::atomic<bool> ready{false};

void Producer() {
    data = "готово";
    ready.store(true); // seq_cst включает release-семантику записи
}

void Consumer() {
    if (ready.load()) { // seq_cst включает acquire-семантику чтения
        auto copy = data; // безопасно: увидели публикацию
    }
}
```

Это одноразовая публикация: один производитель, без последующих изменений `data` и сброса флага. Если потребитель прочитал `false`, он просто ничего не делает. Если прочитал опубликованное `true`, запись строки происходит **happens-before** её чтения. Замена обеих операций на `relaxed` убрала бы нужную синхронизацию обычной строки.

## Подводные камни

- Пример с обычными `int x, y` и конкурентными чтениями/записями содержит UB. Объяснять его результат только кешами или предсказывать допустимые пары значений нельзя.
- `-O0`, `volatile` и задержки не исправляют гонки данных. Аппаратно неделимое чтение обычного `int` тоже не превращает его в C++-атомик.
- `store()` не обещает, что любое следующее по настенным часам `load()` немедленно прочитает эту запись. Допустимое значение определяется отношениями порядка, а не понятием «самое свежее в памяти».
- Не смешивай отношения: **modification order** — полный порядок изменений одного атомика; **happens-before** — частичный порядок, в том числе между потоками; **seq_cst** дополнительно задаёт единый полный порядок для соответствующих атомарных операций.
- Отсутствие data race не делает любую программу последовательно согласованной: пример с `relaxed` выше корректен, но допускает `(0, 0)`. Для привычного последовательного рассуждения нужны соответствующие средства синхронизации, например мьютексы и `seq_cst`-атомики.
- **Memory location** — не байт и не линия кеша: это скалярный объект либо максимальная последовательность соседних битовых полей ненулевой ширины. Разные обычные поля могут быть отдельными локациями, а соседние битовые поля — одной.
- Конкурентные обращения к разным локациям сами по себе не образуют data race, но могут нарушать общий инвариант структуры. Когерентность кешей не заменяет протокол синхронизации.
- Синхронизация не обеспечивает время жизни автоматически: опубликованный объект должен существовать всё время чтения, и его последующие изменения тоже нужно согласовать.

## Саммари

Рассуждай о допустимых наблюдениях и отношениях порядка, а не о буквальном порядке машинных инструкций. Атомарность защищает отдельную операцию; корректная синхронизация связывает операции разных потоков и делает обычные данные доступными безопасно.
