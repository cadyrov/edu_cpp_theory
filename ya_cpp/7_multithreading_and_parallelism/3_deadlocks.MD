# 3. Взаимные блокировки

## Суть

- **Deadlock (дедлок)** — циклическое ожидание: каждый участник ждёт действие другого, и никто не может продолжить. Например, первый поток удерживает A и ждёт B, второй удерживает B и ждёт A.
- Достаточно и одного мьютекса: поток держит его и делает `join()`, а дочерний поток ждёт этот мьютекс.
- **Livelock (лайвлок)** — потоки продолжают действовать и повторять попытки, но полезного продвижения нет. Он не ограничен атомарными операциями.
- Для вложенных захватов установи единый порядок мьютексов во всём коде. Когда нужны сразу несколько мьютексов, используй `std::scoped_lock` (C++17).

## Примеры

### Разный порядок захвата: возможен дедлок

```cpp
#include <mutex>
#include <thread>

int main() {
    std::mutex a, b;
    std::jthread first([&] {
        std::lock_guard lock_a(a);
        std::lock_guard lock_b(b);
    });
    std::jthread second([&] {
        std::lock_guard lock_b(b);
        std::lock_guard lock_a(a);
    });
} // программа может зависнуть при ожидании потоков
```

Исправление: в обоих потоках захватывать сначала `a`, потом `b`, либо заменить обе блокировки на `std::scoped_lock lock(a, b);`.

### Несколько мьютексов через RAII

```cpp
#include <mutex>
#include <utility>

template <typename T>
class SharedResource {
    std::mutex mutex_;
    T value_{};

public:
    friend void swap(SharedResource& lhs, SharedResource& rhs) {
        if (&lhs == &rhs) {
            return; // нельзя дважды передать один std::mutex
        }
        std::scoped_lock lock(lhs.mutex_, rhs.mutex_);
        using std::swap;
        swap(lhs.value_, rhs.value_);
    }
};
```

`scoped_lock` захватывает мьютексы с алгоритмом избежания дедлока и освобождает их в деструкторе. Конкурирующие `swap(a, b)` и `swap(b, a)` не создадут цикл ожидания на этих двух мьютексах. Сам `swap` для `T` не должен создавать новые циклы ожидания.

### Один мьютекс и ожидание потока

```cpp
std::mutex mutex;
std::jthread worker;
{
    std::lock_guard lock(mutex);
    worker = std::jthread([&] {
        std::lock_guard worker_lock(mutex);
        // работа с общими данными
    });
} // сначала освобождаем мьютекс
worker.join(); // затем ждём поток
```

Если перенести `join()` внутрь блока с `lock`, возникнет дедлок: родитель ждёт ребёнка, ребёнок — освобождения мьютекса родителем.

## Подводные камни

- **Голодание (starvation)**: система продвигается, но отдельный поток долго не получает ресурс. Отсутствие дедлока и использование `scoped_lock` не гарантируют справедливость.
- RAII гарантирует освобождение при выходе из области, но не предотвращает зависание внутри неё.
- Автоматический `join()` в деструкторе `jthread` тоже может участвовать в дедлоке. Учитывай обратный порядок уничтожения локальных объектов.
- `scoped_lock` не обещает порядок захвата по аргументам и не устраняет циклы с другими, уже удерживаемыми блокировками или ожиданиями.
- Не передавай в `scoped_lock` один `std::mutex` дважды или мьютекс, которым текущий поток уже владеет, для обычного захвата.
- Под блокировкой избегай вызовов чужих методов, колбэков и виртуальных функций: они могут захватить другие мьютексы или повторно войти в твой объект.
- Если получить данные другого объекта до захвата своего мьютекса, вложенного захвата не будет. Но значения двух объектов уже не образуют единый согласованный снимок — проверь требования операции.
- `sleep_for()` только меняет вероятность проявления ошибки. Отсутствие зависания при нескольких запусках не доказывает корректность.

## Саммари

Не создавай циклических ожиданий. Соблюдай общий порядок захвата или используй `std::scoped_lock` для нескольких мьютексов; освобождай нужные рабочему потоку блокировки до `join()` и контролируй вызовы под мьютексом.
